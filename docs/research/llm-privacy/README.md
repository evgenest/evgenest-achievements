## Журнал решений

| Дата | Решение | Почему |
|---|---|---|
| 2026-09-12 | Локальную LLM на текущем VPS не поднимаем | 2 vCPU, ~2 ГБ свободной RAM, без GPU: влезает только модель ≤2B, качество русского отчёта неприемлемое |
| 2026-09-12 | Апгрейд VPS под локальную модель не делаем | ~20–30 €/мес — дорого для задачи раз в неделю |
| 2026-09-12 | Реальный бенчмарк локальных моделей откладываем | Нужен отдельный harness и загрузка моделей; облачный путь проще проверить первым |
| 2026-09-12 | Направление: облачная LLM с ZDR + обработкой в EU | Данные не хранятся у провайдера и не выходят из EU, без затрат на железо |
| 2026-09-12 | Требование: **ZDR обязателен**, EU — желательно, но не обязательно | Цель — максимально близко к локальной модели: облако только считает, данные нигде не остаются и не идут на обучение |
| 2026-09-12 | Маршрут: **OpenRouter** (аккаунт Business уже есть), не Vercel | ZDR у Vercel только на Pro ($20/мес за место); у OpenRouter ZDR доступен на любом тарифе, комиссия 8% с пополнения — при ~$1/мес это центы |
| 2026-09-12 | Модель: **Nemotron 3 Ultra** (US, ZDR), effort `high` | Нравилось, как пишет отчёты и сводки; `gpt-5.6-luna` слабая даже на `high`. Nemotron в EU нет — US с ZDR признан приемлемым |
| 2026-09-12 | ZDR в коде захардкожен, без переключателя | Fail-closed, как `assertSanitized`: нет ZDR-эндпоинта — запрос падает, а не уходит к провайдеру, который хранит данные |
| 2026-09-12 | Поиск ставок под OpenRouter — серверный `openrouter:web_search` (Exa), вне ZDR | ZDR-поиска у OpenRouter нет: ZDR покрывает только инференс. В запросы уходят только роль/уровень/стек/регион; сама модель (включая шаг, видящий `DEV_PROFILE`) — на ZDR |
| 2026-09-12 | Аккаунт: **личный OpenRouter (Standard)**, не Business | ZDR (`provider.zdr`) работает на любом тарифе; Business нужен только для EU-роутинга, а Nemotron всё равно в US. Комиссия 5.5% вместо 8% |

## Текущий статус

Реализован `LLM_PROVIDER=openrouter` (`src/llm.ts` → `callOpenRouter`). Не задеплоено: нужен секрет `OPENROUTER_API_KEY`.

Проверено локально (без реального ключа): typecheck, тесты, сборка бандла (`wrangler deploy --dry-run`);
тело запроса с подменённым `fetch` содержит `provider: { zdr: true, data_collection: "deny", require_parameters: true }`,
`reasoning: { effort: "high" }`, `response_format: json_schema` со `strict: true`, без `plugins`.
Поиск ставок: тот же ZDR-блок + `tools: [{ type: "openrouter:web_search" }]`.

## Открытые вопросы

1. Если после перехода на ZDR качество устроит — пересмотреть #3: можно ли при такой схеме отдавать модели больше данных (полные тела коммитов, описания PR) без локального препроцессора.
2. Проверить на реальном прогоне, какой провайдер обслужил запрос (ожидается DeepInfra — единственный ZDR-эндпоинт Nemotron 3 Ultra со strict structured output) и не хуже ли fp4-квантизация того, что было через Vercel.
3. Если понадобится EU: перейти на OpenRouter Business (EU-роутинг есть только там), переключить модель на EU-кандидата (см. `02-cloud-zdr-eu.md`) и добавить регион в base URL (`eu.openrouter.ai`).
