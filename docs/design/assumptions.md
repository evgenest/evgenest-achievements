# Принятые допущения: как сняты расхождения

> **Для кого:** автор кода и авторы документов дизайна.
> **Что здесь решает владелец:** ничего; то, на что ему стоит взглянуть, вынесено в [общий README](README.md#принятые-допущения).
> **Что просто к сведению:** всё — какое чтение считать верным там, где решения от 2026-09-19 молчали или расходились.

*Принятое допущение* — мелкое решение, принятое авторами дизайна без владельца; в текстах папок оно помечено этими
словами и дёшево меняется. Списки по папкам: [trends](trends/README.md#принятые-допущения-дёшево-изменить),
[retrospectives](retrospectives/README.md#принятые-допущения),
[local-sources](local-sources/README.md#принятые-допущения-дёшево-изменить); в week-record они помечены в тексте.

## Что считать верным

Везде выбран самый простой путь, совместимый с решениями; правая колонка — то, что действует во всех папках.

| Расхождение | Что действует |
|---|---|
| Ретроспективы опираются на поле `hoursScale`, а в общей схеме записи его не было | Необязательное `hoursScale?: "union-with-main-report"` в схеме v1; корректирующая запись без него в сумму часов не входит |
| Недели длиной 3–5 дней: решения называют только «сравнима 5–9,5» и «короче 3 — вне сравнений» | Одно правило: сравнима только неделя 5–9,5 дня, всё остальное — вне «обычного» и рекордов |
| Рвёт ли источник `sessions` ряд часов: решения говорят «тот же набор `sources`» | Нет — формула [trends/02](trends/02-computation.md#режим-ряда-и-разрыв): время в паре с ИИ в часы не входит |
| Блок «не длиннее 8 строк», а перечисленный состав даёт до 10 | Правило [«что уступает место»](trends/01-reader.md#восемь-строк-что-уступает-место): первыми сокращаются строки о проектах |
| «4 и более записей» — с текущей неделей или без | Без неё: у форка блок впервые выходит в пятом отчёте после R0 |
| Массовые строки: входят ли они в итоги записи | Итоги записи — как в таблице отчёта; `bulk` — их массовая часть; «строки работы» считает читатель. Видимый отчёт в R0 не меняется |
| Обязательные поля записи, которых в старых отчётах нет | У записей `src: "backfill"` стоят заполнители и приближения; читатели считают такие записи слабыми |
| Бэкфилл идёт после R0, когда в state уже есть `history` и `career` | Восстановленные записи добавляются слиянием по `n`; запись, написанную R0, бэкфилл не заменяет; `career` = прежний + суммы восстановленных |
| Формулировка вопроса №5 | Расширена: невидимая запись несёт минуты уже с R0, поэтому ответ нужен до R0, а не до R2 |
| Вопрос №2 не привязан к итерации | Делается вместе с остатком I0: там и так правится защита данных для модели |
| Вопрос №3 — два дела в одной строке | Разделён на №3а (решение: выключить сохранение трасс) и №3б (проверка руками); ссылки «№3» в папках относятся к обоим |
| «Месяц — по дате отчёта», но имя файла — день по UTC | Решает локальная дата `until`; путь строится из UTC-дня, как в `src/run.ts:66-67`. У прогонов по расписанию они совпадают; у ручных без `?date=` могут разойтись на сутки |
| «Все закрытые месяцы, старые первыми, не больше 3 проверок» — свежий месяц не дождался бы очереди | Проверяются три самых свежих закрытых месяца; автоматической пересборки нет, только если номеров недель из готового файла в `history` нет вовсе (вышли из окна, `history` пуста); номер есть, но ушёл в другой месяц → пересборка |
| Список корректирующих в отпечатке сравнивать «с `history`» нельзя: их там нет | Список хранится, но сам не сравнивается; поздний корректирующий отчёт — повод для `force=1` |
| Бюджет ретроспективы «типично 14, максимум 18–25» не сходится с собственными потолками | Типично 14, арифметический потолок 31–33 из 50; тест «обычный месяц ≤ 18» остаётся |
| Активные дни: год — сумма месяцев, месяц — объединение дней | Месяц — объединение дней, иначе сумма со знаком «≈»; в году день на стыке месяцев может быть учтён дважды |
| «Перенос опоздавших сохраняет суммы» записан в тесты ретроспектив | Это свойство трендов; месяц считает по неделе доставки и ничего не переносит |
| «Побеждает самое строгое правило» при нескольких машинах | Worker обеспечивает только `counters` против `text`; режим `off` он увидеть не может — `off` ставится на каждой машине |
| На пути проверочного запроса «ноль записей» или одна | Одна — кэш проверки приватности на час; приёмка требует «ноль `list()`» |
| 15–26 внешних запросов — весь прогон или только сбор | Весь прогон (измерено); после I1 — 16–27 (оценка) |
| Грейс — и часть дизайна, и открытый вопрос | Заложен по умолчанию; документы local-sources говорят, что изменится при ответе «нет» на №4 |
| Пропажа `history` незаметна (деплой кода старше I0-минимума, потеря KV) | Строка лога `history_missing` без изменений в видимом отчёте; пропажу восстановленных бэкфиллом записей показывает только `records-rebuild --check` |

## Решения после проверки на прочность (2026-09-19, вечер)

Четыре решения приняты уже после проверки дизайна на прочность; они главнее всего остального и внесены во все
папки.

| Решение | Где записано |
|---|---|
| Защита от мусорного прогона стоит внутри `runWeekly`: `since ≥ until` или ручной прогон короче суток → строка лога и выход без записи отчёта, state и Telegram; ответ 409 в `/run` — ранняя подсказка человеку. Приёмка I0-минимума: «сообщение доставлено дважды → вторая доставка ничего не пишет» | [06-change-map](local-sources/06-change-map.md#изменения-в-существующих-файлах-src), [итерации](local-sources/README.md#итерации) |
| I0-минимум: `advanceState` переносит незнакомые поля верхнего уровня state как есть. Откат деплоя на код не старше I0-минимума ничего не стирает; код старше — стирает `history`, `career`, журнал учтённого. В данные для модели такие поля не попадают | [05-operations](local-sources/05-operations.md#откат-деплоя-и-потеря-kv), [week-record/02](week-record/02-backfill-and-recovery.md#деплой-старого-кода) |
| Работа машины, молчавшей дольше ~28 суток, в отчёт не попадает и счётчиком не видна — названный предел, нового механизма нет | [07-selection, S14](local-sources/07-selection.md#сценарии) |
| Корректирующие отчёты после выхода I1 не обещаны и как аварийное средство | [принципы local-sources](local-sources/README.md#зафиксированные-принципы), [05-operations](local-sources/05-operations.md#откат-деплоя-и-потеря-kv) |

*Принятое допущение* к первому решению: сообщение очереди, попавшее под защиту, один раз повторяется через 90 секунд
(`message.retry`), чтобы пережить кеш KV; вторая попытка с тем же исходом подтверждается без работы.
