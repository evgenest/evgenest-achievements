> задан (вопрос №1); сообщение в Telegram — вопрос №8; оба — в [общем README](../README.md).
>
> **Что просто к сведению:** всё остальное. *Принятое допущение* помечает места, где решения от 2026-09-19 молчали
> и выбран самый простой вариант; общий список — в [README папки](README.md#принятые-допущения).

Ссылки `src/файл:строка` проверены чтением кода 2026-09-19; факты о платформе сверены с документацией
Cloudflare и GitHub в тот же день. Живым прогоном не проверено ничего — кода ещё нет.

## Конвейер целиком

Один запуск получателя очереди делает до трёх дешёвых проверок и не больше одной сборки; всё до вызова
модели — чистые функции и чтение файлов.

| № | Шаг | Запросы наружу |
|---|---|---|
| 1 | Разбор сообщения; переменная выключена → подтвердить и выйти; `message.attempts > 1` → уведомить и выйти | 0–1 |
| 2 | `loadState`: `history`, `lastRunUntil` (KV — не внешний запрос) | 0 |
| 3 | `duePeriods(...)` — кандидаты; пусто → выйти | 0 |
| 4 | Для каждого кандидата: `getFile` файла периода → сравнить отпечаток; первый несовпавший собирается | 1–3 |
| 5 | Чтение недельных файлов и пробы `<день>_local.md` | 4–6 + 4–6 |
| 6 | Правила приватности; при локальном тексте — проверка приватности репозитория отчётов | 0–1 |
| 7 | `aggregatePeriod(...)` — числа; очистка текстов, сборка входа, поиск секретов | 0 |
| 8 | `callModel(...)`; у OpenRouter второй, текстовый вызов — запасной путь | 1–2 |
| 9 | Фильтр ответа → `renderPeriod(...)` → встроить запись периода | 0 |
| 10 | `putFile` с `sha` из шага 4; при ответе 409 — один повтор (перечитать и записать) | 1–3 |
| 11 | Telegram; при ошибке разметки — повтор без неё | 1–2 |
| 12 | После успешной сборки — следующее сообщение `{ kind: "retro", built }` с задержкой 60 с | 0 |

Для года шаги те же, только вместо недельных файлов читаются месячные. State ретроспектива не пишет.

## Какой период положен

Период вычисляет получатель из state в момент своего запуска: сообщение `{ kind: "retro" }` означает
только «проверь, не пора ли». Считает чистая функция `duePeriods(history, lastRunUntil, tz)`.

1. **Месяц закрыт**, когда локальная дата `lastRunUntil` попала в более поздний месяц.
2. **Кандидаты** — закрытые месяцы, у которых в `history` есть хотя бы одна запись; берутся три самых
   свежих, проверяются от старого к новому; собирается первый, у которого нет файла или устарел отпечаток.
3. **Год.** Если ни один месяц сборки не потребовал, а локальный месяц `lastRunUntil` — январь, проверяется
   прошлый год. Так год всегда идёт отдельным сообщением после декабря.
4. **Цепочка.** После успешной сборки ставится ещё одно сообщение; в `built` копятся собранные периоды, и
   период из `built` повторно не собирается — предохранитель от платного зацикливания. Запуск без сборки
   цепочку не продолжает.

Почему три месяца, а не всё окно *(принятое допущение)*: откаты и свежие пропуски живут в последних
неделях, а каждая проверка — запрос. Старые пропуски закрывают годовой шаг и ручной маршрут. От урезанной
пересборки, когда недели старого месяца уходят из окна в 53 записи, защищает правило «входы сократились».

## Месяц — по дате отчёта

Неделя целиком относится к тому месяцу, в который попадает локальная дата её `until` — для пятничного
запуска по расписанию это и есть дата файла отчёта; год — по месяцу.

- **Объясняется одной фразой** и для прогонов по расписанию совпадает с именами файлов: отчёты,
  датированные октябрём, и есть октябрь.
  Каждая неделя — ровно в одном месяце, поэтому сумма недель равна месяцу, а сумма месяцев — году.
- **Закрытый месяц никогда не содержит самую свежую неделю.** Неделя, чей прогон закрыл сентябрь, сама
  датирована октябрём. Привычный цикл «откат → другая модель → повтор» меняет только её: входы сентября те
  же, повторное сообщение ничего не тратит. При правиле «по середине периода» свежая неделя попадала бы в
  только что закрытый месяц, и каждый такой цикл портил бы готовый файл.
- **Цена правила.** Неделя 24 сентября — 1 октября почти вся сентябрьская, а считается октябрьской. Поэтому
  в шапке всегда стоят фактический диапазон дат и номера недель, а рядом с суммой — «в среднем за неделю».
- **Уточнение про имя файла** *(принятое допущение)*. Имя недельного файла — день `until` по UTC
  (`src/run.ts:66-67`), а месяц берётся по локальной дате в поясе `tz` записи. У владельца для прогонов по
  расписанию и с `?date=` они совпадают; расходятся на сутки далёкие пояса (от UTC−9 на запад, от UTC+10 на
  восток) и ручные прогоны без `?date=` (`until` — текущий момент, `src/index.ts:84`), сделанные между
  локальной полуночью и полуночью UTC. Главной считается локальная дата; путь строится из `until`, как в `src/run.ts`.

## Отпечаток входов: повтор ничего не тратит

Первым читается сам файл периода — он нужен и ради `sha` для записи; в его записи лежит список недель, из
которых он собран: `inputs: [{ n, since, until, commits, minutes }]`. Совпало с `history` — выход.

| Что оказалось | Что делает получатель |
|---|---|
| Файла нет (404) | Сборка |
| `inputs` совпал с неделями месяца из `history`, `force` нет | Лог `retro_up_to_date`: 0 вызовов модели, 0 сообщений |
| `inputs` не совпал (неделю пересобрали, добавилась, ушла в другой месяц) | Пересборка; файл и сообщение с пометкой «обновлено» |
| Номеров из `inputs` в `history` нет вовсе: они меньше наименьшего `n` в `history` (недели вышли из окна) или `history` пуста (потеря KV, код старше I0-минимума) | Не пересобирается: лог `retro_inputs_shrunk`, уведомление; лечится `records-rebuild` или `force=1`. Если номер в `history` есть, но относится к другому месяцу или изменился (двойной откат недели, закрывшей месяц), — это строка «не совпал»: пересборка |
| Файл есть, запись в нём не читается (правили руками) | Считается готовым; лечится `force=1` |
| `force=1` с ручного маршрута | Пересборка без сравнения |

- В отпечаток **не входят** время сборки, модель, версия словаря, текст файлов: любое поле, меняющееся от
  запуска к запуску, превратило бы еженедельную проверку в еженедельный платный вызов.
- Список учтённых корректирующих (`correctives`) лежит рядом, но сам не сравнивается — это до десяти
  запросов каждую неделю; поздний корректирующий отчёт — повод для `force=1` *(принятое допущение)*. К
  выходу R3 новых таких отчётов не будет: после I1 отчёт общий.
- Отпечаток года — `months: [{ period, weeks, minutes }]`; сравнивается только в январе *(принятое
  допущение)*. Маркеров «сделано» в KV и в state нет: признак живёт в самом файле и переживает потерю KV.

## Какие файлы читаются и как

Читается только репозиторий отчётов, только токеном отчётов и только по именам, выведенным из `history`;
списка папки нет, `GITHUB_TOKEN` в запуске не участвует.

| Файл | Путь | Форма ответа | Если 404 |
|---|---|---|---|
| Файл периода | `monthly/YYYY-MM.md`, `yearly/YYYY.md` | обычный JSON: в нём `sha`, текст в base64 | файла нет → сборка |
| Недельный отчёт | `<день until>.md` | сырой текст (`Accept: application/vnd.github.raw+json`) | неделя идёт только числами |
| Корректирующий | `<день until>_local.md` — проба для каждой недели | сырой текст | норма: файла не было |
| Месячные файлы для года | `monthly/YYYY-01…12.md` | сырой текст | месяц достраивается или «нет данных» |

- Сырой ответ не содержит `sha` (сверено с документацией GitHub), поэтому файл периода читается обычным
  JSON; он мал (5–15 КБ), раскодирование base64 — доли миллисекунды.
- Недельные отчёты — 6–35 КБ при пороге Contents API в 1 МБ; список папки у него ограничен 1000 файлами.
  Раз имена берутся из `history`, файлы-сироты отменённых прогонов не читаются никогда. Жёсткий потолок
  кода: не больше 10 недельных файлов и 10 проб на месяц; чтение — параллельно, запись одна.

**`getFile` и `putFile`.** Сегодня `commitFile` сам читает `sha` и сам пишет (`src/github.ts:286-311`). R3
делит его на две функции; `commitFile` остаётся обёрткой — недельный прогон не меняется ни на запрос.

```ts
getFile(env, config, path, opts?: { raw?: boolean }): Promise<{ text: string; sha?: string } | null>  // 404 → null
putFile(env, config, path, text, message, sha?): Promise<string>       // html_url; ответ 409 → ошибка «конфликт»
// commitFile(path, text, message) = getFile(path) → putFile(path, text, message, sha)
```

## Бюджет запросов

Ретроспектива — отдельный запуск со своим лимитом в 50 запросов наружу; к недельному прогону она не
прибавляет ничего.

| Запуск | Запросы наружу | Откуда известно |
|---|---|---|
| Недельный прогон сегодня; R3 прибавляет +0 (постановка в очередь — не внешний запрос) | 15–26 из 50 | измерено по логам владельца, тариф Workers Free; «+0» проверяет тест-счётчик |
| Обычная неделя, собирать нечего | 1–3, в январе до 13 | расчёт |
| Сборка месяца, типично: 1 проверка + 5 + 5 + модель + запись + Telegram | 14 | расчёт |
| Месяц из 6 недель: 3 проверки, все запасные пути, конфликт записи | 23 | расчёт |
| Сборка года: файл года + 12 месячных + модель + запись + Telegram | 16–20 | расчёт |
| Январь, годовой шаг достраивает пропущенный месяц (редкий случай) | до 33 | расчёт |
| Арифметический потолок: 10 недель в месяце (даёт только десяток ручных прогонов) | 31 | расчёт |

Обращения к KV и к очереди идут по отдельному лимиту в 1000 на запуск; время запуска — до 15 минут.
Процессорное время **не измерено**: ожидание — не тяжелее недельного прогона (37–113 мс, на Free наблюдаемо
проходит, Cloudflare этого не гарантирует); замер в workerd входит в приёмку R3.

## Как складываются числа

Все числа считает чистая функция `aggregatePeriod(records, correctives)`; модель получает их готовыми.

- **Основная неделя** — из `history`, **корректирующая** — из записи в её файле. Если номер `n` этой записи
  не совпал с неделей из имени файла или записи версии 1 в файле нет, файл не учитывается вовсе.
- **Часы двух файлов складываются**, когда у корректирующей записи стоит `hoursScale:
  "union-with-main-report"`; иначе её минуты показаны сноской *(принятое допущение)*. Вклад корректирующих
  хранится отдельно (`localMinutes`) — из него строка «из них по локальным репозиториям».
- **Активные дни** — объединение ключей `dayMap` всех записей месяца. У записи без полного `dayMap`
  (восстановлена из старого отчёта; есть свёрнутая приватная строка) берётся её `activeDays`, итог получает
  знак «≈» *(принятое допущение)*. У года — сумма месяцев; день на стыке месяцев может быть учтён дважды — известная погрешность.
- **PR и issues** — только событийные счётчики. **Проекты** объединяются по имени; строки без имени — в
  одну строку «приватные проекты». Опоздавшая работа не переносится: месяц считает по неделе доставки.
  Строки кода хранятся в записи, но не показываются.
- **Год** — сумма месячных записей; мини-график недель — из их `inputs` и `correctives`, рекорды — из
  `bestWeek` и `bestStreak`.

## Вход модели и схема ответа

Модель получает готовые числа и очищенные тексты уровня ниже; коммитов, GitHub и state она не видит.

```ts
interface RetroPayload {                       // src/retro/payload.ts — свой список разрешённых ключей
  period: string;                              // "2027-10" | "2027"
  facts: { weeks; activeWeeks; activeDays; daysInPeriod; hours; localHours; prsMerged; deployments;
           projects: { name: string; hours: number | null; weeks: number; local?: true }[];
           prev?: { hours: number; activeDays: number } };
  weeks?:  { n: number; since: string; until: string; report: string | null; local: string | null }[];  // месяц
  months?: { period: string; report: string | null }[];                                                 // год
}
const MONTH_ANSWER = z.strictObject({
  headline: z.string(), story: z.string(),     // заголовок до 90 знаков (длиннее — обрезает код); два абзаца
  highlights: z.array(z.strictObject({ text: z.string(), project: z.string().optional() })),   // 3–6
  projectArcs: z.array(z.strictObject({ project: z.string(), arc: z.string() })),              // до 5
  growth: z.string(), telegramMessage: z.string(),   // «что месяц говорит о тебе»; сообщение до 900 знаков
});
const YEAR_ANSWER = z.strictObject({ headline: z.string(), story: z.string(), growth: z.string(),
  themes: z.array(z.strictObject({ title: z.string(), text: z.string() })), telegramMessage: z.string() });
```

- **Очистка текста** `stripForRetro`, по порядку: вырезать блоки `<details>…</details>` и все
  HTML-комментарии (значит, и запись) → ссылки заменить их текстом → `private-project-N` заменить на
  «приватный проект» → словарь замен, если он задан → `scrubSecrets` → обрезать до 12 000 знаков. Очистка
  идёт по тегам, а не по русским заголовкам, и переживёт смену вёрстки и языка. `null` вместо текста —
  неделя «только числа» ([03-privacy-and-failures.md](03-privacy-and-failures.md)).
- **Объём** (замер на готовых отчётах): без списков коммитов отчёт — 3–9 тыс. знаков, месяц — 15–45 тыс.,
  примерно один недельный вызов (10–19 тыс. токенов); год — около 60 тыс. знаков. **Ответ:** пункты с
  проектом, которого не было во входе, отбрасывает код; затем — подметание словарём, если он задан.
- **Промпт** лежит в `src/i18n/` рядом с недельным: та же роль тренера и тот же `DEV_PROFILE` *(принятое
  допущение)*. Правила: писать только по данным; итоги брать из `facts`, самому не складывать; периоды не
  сравнивать как «лучше» и «хуже»; строки и число коммитов — не достижение; приватные проекты между
  неделями не связывать; тихий период — бережно.
- **`callModel(schema, instructions, prompt, normalize?)`** — общий вызов, вынесенный из `src/llm.ts`.
  Функции провайдеров уже принимают схему и инструкции (`src/llm.ts:127`, `224`, `317`); к недельному
  ответу привязаны только тип `ResultSchema` (`src/llm.ts:21`) и `normalizeLlmAnswer` (`src/llm.ts:108`).
  Запасной путь OpenRouter и правило «только без хранения данных у провайдера» наследуются
  (`src/llm.ts:310-333`).

## Запись периода (`PeriodRecord`)

Запись периода встраивается в конец файла так же, как запись недели, и служит трём целям: отпечаток
входов, числа для года, заголовок для хроники.

```ts
export interface PeriodRecord {                  // src/retro/types.ts
  v: 1; kind: "month" | "year"; period: string;  // "2027-10" | "2027"
  from: string; to: string;                      // since первой недели и until последней, ISO UTC
  generatedAt: string; tz: string; llm: string;  // llm — "provider/model"
  privacy: "full" | "redact" | "skip";           // ТЕКУЩИЙ режим в момент сборки
  updated?: true; partial?: true;                // пересобран · неполный (у года — есть месяцы «нет данных»)
  headline: string;                              // из него кодом строится хроника года
  inputs?: { n: number; since: string; until: string; commits: number; minutes: number }[];   // месяц
  correctives?: { n: number; commits: number; minutes: number; summed: boolean }[];           // месяц
  months?: { period: string; weeks: number; minutes: number }[]; missing?: string[];          // год
  weeks: number; activeWeeks: number; daysInPeriod: number; activeDays: number; activeDaysApprox?: true;
  minutes: number; localMinutes: number;         // localMinutes — часть minutes из корректирующих отчётов
  commits: number; additions: number; deletions: number;
  bulk?: { commits: number; additions: number; deletions: number };
  prsOpened: number; prsMerged: number; issuesOpened: number; issuesClosed: number;
  ci: [ok: number, fail: number]; deployments: number;
  cost?: { currency: string; employee: number; freelance: number };   // нет, если валюта менялась
  ai?: { minutes: number; sessions: number };    // после I3; с minutes не складывается никогда
  bestWeek?: { n: number; minutes: number }; bestStreak: number;      // bestWeek — только недели в 5–9,5 дня
  projects: { name: string | null; minutes: number | null; commits: number; weeks: number;
              private?: true; local?: true; counters?: true }[];
  achievements: string[];
}
```

Правила версий — те же, что у записи недели ([../week-record/01-schema.md](../week-record/01-schema.md#версии)).
Всё числовое складывается: на этом стоят проверки «сумма недель = месяц» и «сумма месяцев = год». Запись
строится после правил приватности: имён, скрытых текущим режимом, в ней нет.

## Ручной маршрут

Один маршрут под тем же секретом, что `/run`, собирает любой закрытый период по требованию и умеет
пересобрать его принудительно: `POST /retro?period=YYYY-MM|YYYY[&force=1]`, заголовок
`Authorization: Bearer <RUN_SECRET>`.

| Ответ | Когда |
|---|---|
| 404 | `RETROSPECTIVES` не включена — как любой неизвестный адрес (`src/index.ts:58-60`) |
| 403 · 400 | неверный секрет · `period` не похож на `YYYY-MM` или `YYYY` |
| 409 | период ещё не закрыт; для месяца — ещё и когда в `history` нет его недель *(принятое допущение)* |
| 202 | сообщение `{ kind: "retro", period, force }` поставлено в очередь без задержки |

- Работа уходит в очередь по той же причине, что у `/run`: фоновая работа HTTP-запроса ограничена
