# 01. Архитектура

> **Для кого:** тот, кто пишет код I1–I3. Владельцу достаточно раздела «Один общий отчёт на неделю»; замеры на
> Workers Free — в [05-operations.md](05-operations.md#workers-free-что-измерено).
> **Что здесь решает владелец:** ничего нового. К документу относится пункт №4 общего списка («грейс»); он объяснён в
> [07-selection.md](07-selection.md), сам вопрос — в [общем README](../README.md).
> **Что просто к сведению:** компоненты, точка врезки, вид отчёта, проверочный запрос, список учтённого, слияние.
> Схема снимка и порядок его приёма вынесены в [10-wire-and-ingest.md](10-wire-and-ingest.md).

Частые слова. **Снимок** — JSON с событиями одной машины, один ключ в KV. **Журнал учтённого (ledger)** — короткие
хеши уже посчитанных коммитов внутри state. **Список учтённого** — его копия для машин. **Проверочный запрос** — `GET`,
которым collector перед отправкой спрашивает Worker, можно ли слать текст и что уже учтено. **Внешний запрос**
(subrequest) — исходящий запрос Worker'а наружу; на Free их 50 на вызов.

## Компоненты

Новое живёт в `collector/` и `src/ingest/`; в существующий конвейер оно входит в одной точке.

| Компонент | Где живёт | Ответственность |
|---|---|---|
| **collector** | `collector/` в этом же репозитории, запускается на машине | Найти репозитории, определить режим каждого (`collector/rules.ts`: `text` / `counters` / `off`), прочитать `git log` и метаданные сессий, собрать снимок, проверить, отправить. Каждый push — полная замена снимка; на машине хранится только выбрасываемый кэш |
| **формат передачи** ([10](10-wire-and-ingest.md)) | `src/ingest/wire.ts`, `src/ingest/guard.ts` — без `Env`, общие для Worker'а и collector'а | Типы снимка, лимиты, регулярные выражения, рукописный валидатор (guard). **Collector строгий** (незнакомый ключ — ошибка до отправки), **Worker терпимый** (проверяет типы известных полей, незнакомые ключи считает в сноску): тело хранится неразобранным, строгость на Worker'е приватности не добавляет, а collector чуть новее Worker'а не должен «исчезать» на неделю |
| **приём** | `src/ingest/handler.ts` | `GET` — проверочный запрос. `PUT` — принять снимок, не разбирая тело, положить в KV ([10](10-wire-and-ingest.md#приём-снимка)) |
| **store** | `src/ingest/store.ts` | В прогоне: прочитать индекс машин и их снимки, проверить формат. `machineId` берётся из имени ключа; снимок с другим `machineId` в теле отклоняется. Битый снимок пропускает машину, а не роняет неделю |
| **select + ledger** | `src/ingest/select.ts`, `src/ingest/ledger.ts` | Чистая функция: (state, снимки, GitHub-коммиты, since, until) → события недели + следующий журнал |
| **accounted** | `src/ingest/accounted.ts` | `buildAccounted` (чистая), `publishAccounted`, `isComplete` — список учтённого и проверка полноты снимка |
| **visibility** | `src/ingest/visibility.ts` | `localTextGate(privacy, reportsPrivate)` → `{ allowed, why }`; шов `resolveLocalVisibility` — до I5 всегда «приватно» |
| **merge** | `src/ingest/merge.ts` | Превратить выбранное в `RepoActivity[]` и влить в `WeekActivity` до `applyPrivacy` |

## Точка врезки

Врезка одна — `src/run.ts`, между `collectWeekActivity` и `applyPrivacy` (сегодня `src/run.ts:40-41`); после
`saveState` (`src/run.ts:71`) добавляется публикация списка учтённого.

```
{ state, key: SK, keys } = loadStateWithLineage(env)  // те же 1 list + 1 get, что сегодня; плюс ключи цепочки state
collected = collectWeekActivity(env, config, since, until)
if (env.INGEST_TOKEN) {
  snapshots      = loadSnapshots(env)               // сбой KV / ноль годных → [], никогда не бросает
  incomplete     = snapshots.filter(s => !isComplete(s.meta.through, keys, SK))   // НЕ выбрасываются: счётчик и сноска
  reportsPrivate = await checkReportsRepo(env)      // +1 внешний запрос; определённый ответ → ingest:v1:policy
  gate           = localTextGate(config.privacy, reportsPrivate)          // { allowed, why }
  sel            = selectLocal(state.local, snapshots, collected, since, until)
  merged         = mergeLocal(collected, sel, gate)   // + пересчёт итогов
} else {
  merged = collected                                // ноль обращений к KV, ноль новых внешних запросов
  sel    = { next: state.local ? appendGithubKeys(state.local, collected) : undefined }
}
week = applyPrivacy(merged, policy)                 // …отчёт → запись файла → Telegram…
saveState(advanceState(state, week, ids, rates, { record, local: sel.next }))
publishAccounted(env, <новый state>, <входной state>)  // try/catch, 2 повтора; прогон не роняет никогда
```

- С токеном выбор запускается **всегда**, когда `since < until`, — даже при нуле годных снимков и при сбое чтения KV:
  выбрано пусто, но журнал создаётся, граница `from` закрепляется, GitHub-коммиты прогона записываются. Иначе
  зеркальные коммиты недели задвоились бы опоздавшими локальными копиями.
- Без токена `selectLocal` не вызывается. Если `state.local` уже есть (функцию выключили), в него чистой функцией,
  без KV, дописываются ключи GitHub-коммитов прогона; если его нет — state форка не меняется. Сигнатуру
  `advanceState(…, extras)` вводит R0 ([../week-record/](../week-record/README.md)).
- **Кто может стереть журнал.** Сегодня `advanceState` собирает state из явного списка полей (`src/state.ts:78-100`)
  и незнакомые поля молча теряет. I0-минимум это меняет: незнакомые поля верхнего уровня переносятся как есть. Поэтому
  откат деплоя на любой код **не старше I0-минимума** `local` не стирает: журнал едет дальше нетронутым — устаревшим
  на недели старого кода, но целым. Стирает его только код **старше I0-минимума**; после возврата журнал стартует
  заново с `from = since`. Что при этом теряется и как лечится — в
  [05](05-operations.md#откат-деплоя-и-потеря-kv).
- Выход `selectLocal`: `{ picked, next, dropGithubShas, counters }`. GitHub-репозиторий, у которого после
  `dropGithubShas` не осталось коммитов, удаляется; итоги пересчитываются.

## Один общий отчёт на неделю

После I1 выходит один отчёт: локальные репозитории — строки той же таблицы проектов, со сводками той же модели, в том
же файле `<REPORTS_DIR>/<день>.md`; отличие — одна сноска о здоровье локальных источников.

```
| Проект            | Коммиты | + строк | − строк | Язык |
| my-forge-project  |      40 |  12 000 |     500 | —    |
_Локальные источники: 40 коммитов · опоздавших 0 · отложено 0 · сгорело 0 ·
машины: 1 на связи, 0 молчат > 48 ч, 0 отклонены._
```

- Часы считаются на **одной общей шкале времени** по всем репозиториям — так уже устроен расчёт (`src/hours.ts:6-7`,
  `buildCommitTimeline` — `src/hours.ts:50`): локальные коммиты не удваивают время, занятое GitHub-коммитами.
- Корректирующие отчёты `<день>_local.md` — только для недель, вышедших до I1 ([05](05-operations.md)); ретроспективы
  складывают два файла одной недели как одну неделю ([../retrospectives/02-pipeline.md](../retrospectives/02-pipeline.md)).
- Строки загруженных извне документов (PDF, письма, офисные файлы, lock-файлы) — не объём работы: в отчёте и в записи
  недели показывается «сырые − загруженные» (поле `imported` — в [10](10-wire-and-ingest.md)), со сноской.
- Репозиторий «только цифры» при `full`: строка `local/3f9a1c20b7e4` и пометка «_Только цифры: репозиторий передан
  без текста._» При `redact`: строка `private-project-2` и обычная пометка о скрытом.
- Текст скрыт Worker'ом → сноска называет причину и команду: «_Текст локальных репозиториев скрыт: репозиторий
  отчётов публичный. Проверить: `bun run collector scan`._» (после I2 — `doctor`). Неполный снимок → «_снимок машины собран до отката —
  часть коммитов приедет опоздавшими_».
- В первую локальную неделю в столбце изменений — «—» и строка «подключены локальные источники». Модель получает
  `localCommits`, `lateCommits` и одну фразу в промпте — чтобы не хвалить за всплеск от опоздавшей прошлой недели.

## Проверочный запрос

Один запрос, один контракт: им пользуются `doctor`, `scan` и начало каждого `push`.

```
GET /ingest/v1/<machineId>            Authorization: Bearer <ingest-token>
200 { "supported": [1],
      "text": { "allowed": true | false, "why": "ok" | "privacy" | "reports-public" | "reports-unknown" },
      "publicHosts": [],
      "accounted": <текст ключа ingest:v1:accounted как есть> | null }
```

| Вопрос | Ответ |
|---|---|
| Что значит `why` | Одна человеческая причина. `ok`: `PRIVATE_REPOS=full` и репозиторий отчётов подтверждённо приватный. `privacy`: режим не `full`. `reports-public`: репозиторий отчётов публичный. `reports-unknown`: проверить не удалось. Сырых полей `privacy` и `reportsPrivate` в ответе нет |
| Как собирается ответ | **Склейкой строк**: список учтённого вставляется как есть, без разбора — ключ пишет только сам Worker через `JSON.stringify`. `list()` на этом пути нет |
| Кто проверяет приватность репозитория отчётов | Сам запрос. `ingest:v1:policy` = `{ repo, reportsPrivate, checkedAt }`, срок жизни 3600 с. Ключа нет, он истёк или `repo !== env.REPORTS_REPO` → живая проверка `GET /repos/<REPORTS_REPO>` токеном отчётов (`visibility === "private"`; поля нет — `private === true`) и запись ключа — **единственная допустимая запись на этом пути**. `false` пишется только при определённом ответе GitHub; при ошибке — `reports-unknown`, ключ не трогается. Утёкший токен вызовет не больше одного обращения к GitHub в час. Недельный прогон всегда проверяет заново и обновляет ключ |
| Что делает collector при `allowed: false` | Шлёт все репозитории `text` цифрами (`textDowngraded`) и называет причину одной фразой |
| Запрос не удался или ответ не разбирается | **Push не делается**, повтор через час: слать вслепую значило бы положить в KV лишний текст. `accounted: null` → полное окно, метка пустая |
| Что удалено | Прежний вариант «`PUT` с `Content-Length: 0`» и ритуал «сначала `GET /ingest/preview`». `publicHosts` до I6 — пустой массив |

## Список учтённого и метка `through`

Всё, что collector'у нужно знать об уже учтённом, Worker публикует одним ключом KV; это чистая производная журнала из
state, и пишет её только Worker.

```ts
// src/ingest/accounted.ts — KV "ingest:v1:accounted", без срока жизни; метаданные ключа: { basis, through, entries, bytes }
export interface AccountedList {
  v: 1;
  basis: string | null;        // ключ state, текущего на момент записи: "state:<ISO>"
  through: string | null;      // ключ state, чей журнал опубликован (при грейсе — предыдущий); для collector'а непрозрачен
  from: string | null;         // нижняя граница журнала того же state: старше collector не шлёт
  titlesSince: string | null;  // lastRunUntil того же state — для заголовков сессий (I3)
  sha: string;                 // склеенные 10-hex начала SHA всех записей журнала, локальных и gh:, без повторов
  k: string;                   // склеенные 12-hex hk
}
```

- Когда пишется: после `saveState`; в `DELETE /state/latest` после удаления; самолечение в `POST /run` и
  `GET /ingest/preview`, если `basis` ≠ ключу текущего state (например, после ручного `wrangler kv key delete`).
- Размер (оценка варианта дизайна, не замер): обычно 8–12 КБ, худший случай ≈ 115 КБ, потолок 256 КБ — сверх него
  публикуются только локальные записи, в лог идёт `accounted_truncated`.
- Метку `through` collector возвращает заголовком `X-Accounted-Through`; Worker кладёт её в метаданные снимка. По ней
  прогон и ручной `/run` узнают, полон ли снимок. Правила и обоснования — в [07-selection.md](07-selection.md).

## Что collector не отправляет

Правило одно, на три случая; снимок остаётся чистой функцией от (состояние git, список учтённого).

| Что Worker знает о коммите (по списку) | Что делает collector |
|---|---|
| оба ключа: `sha10` есть в `sha` **и** `hk12` есть в `k` | не отправляет вовсе (`commitsOmittedAccounted`) |
| ровно один из двух | отправляет **без текста** (`commitsTextWithheld`) |
| ни одного | отправляет как обычно (с текстом, если режим `text` и Worker разрешил) |

Кроме того, не уходят: коммиты старше `from` (`commitsBelowFloor`); репозитории `off` (по ним даже не запускается
`git log`) и сессии из них; заголовки сессий без человеческого промпта не раньше `titlesSince` (`titlesOmitted`).

Срок: текст коммита лежит в KV, пока коммит не учтён или учтён последним прогоном. У работающей машины он исчезает
при первом push после следующего прогона (не позже часа), у замолчавшей или при убранном `INGEST_TOKEN` — не позже
9 суток после последнего push. Сразу — `DELETE /ingest/v1/<machineId>`.

## Слияние

Локальный репозиторий становится обычной строкой недели; сколько о нём видно, решают режим на машине и политика
Worker'а, и строгая сторона всегда побеждает.

| Режим на машине | Что пришло | `full`, текст разрешён | `full`, текст не разрешён | `redact` | `skip` |
|---|---|---|---|---|---|
| `text` | имя, тексты коммитов, даты, строки | имя и сводка | `local/<id>`, «только цифры», причина в сноске | `private-project-N` | удалён |
| `counters` | даты и строки, `name: null` | `local/<id>`, «только цифры» | то же | `private-project-N` | удалён |
| `off` | ничего | нет нигде | нет | нет | нет |

| Правило слияния | Как устроено |
|---|---|
| Форма строки | Каждый локальный репозиторий → `RepoActivity`: `fullName = "local/<id>"`, `isPrivate: true`, `local: true` (флаг переживает скрытие и никого не называет), `url: ""`, `ciSuccess/ciFailure/deployments: 0`, `language: null` |
| Имя | `displayName`: `<name>` в режиме `text` (при совпадении имён — `<name>~<id4>`), иначе `local/<id>`. Имя, не прошедшее регулярное выражение или похожее на секрет (`findSecret`), заменяется на `local/<id>` + счётчик — иначе защита данных для модели уронила бы **весь** прогон |
| Две машины, разные режимы | Побеждает **самое строгое**: есть копия `counters` — репозиторий идёт цифрами. Режим `off` Worker увидеть не может (с такой машины ничего не приходит), поэтому `off` ставится на каждой машине. Имя для `id` — из любой `text`-копии (при споре — меньший `machineId`) |
| Текст не разрешён | Текст локальных репозиториев **и заголовки сессий** отбрасываются, если `gate.allowed === false` в этом прогоне — даже при `full` и даже если «непослушный» клиент текст прислал. Причина ложится в `week.local.textHidden` и в сноску |
| Обработка текста | `headline`, `name` и `title` сессии проходят вырезание секретов, обрезку и обезвреживание markdown/HTML до `report.ts` (`title` при срабатывании `findSecret` → «—»); `message` — только вырезание и обрезку |
| Порядок и резерв | Общий список сортируется по дате последнего коммита, затем по `fullName`: нумерация `private-project-N` детерминирована. Заявка `claim` до I5 не читается: шов видимости всегда отвечает «приватно» |

Итог слияния — `WeekActivity.local`; им владеет `applyPrivacy`:
`{ commits, late, deferred, expired, unknownKeys, namesReplaced, textHidden?, machines: { seen, stale, rejected, incomplete } }`

| | `full` | `redact` | `skip` |
|---|---|---|---|
| Локальные репозитории | как есть | `private-project-N`, цифры | удалены, итоги пересчитаны |
| `week.local` (числа) | есть | есть | **обнулены**; остаётся только строка здоровья машин |
| Ключи `localCommits`/`lateCommits` в данных для модели | есть | есть | нет |
| `off-grid` (I2) | по `week.local.commits` после приватности | то же | не срабатывает |
| Журнал учтённого | продвигается | продвигается | продвигается (смена `skip → redact` прошлое не возвращает) |
| I3: время в паре с ИИ, общая сумма | есть | есть | есть |
| I3: разбивка по проектам | есть | `private-project-N` | только проекты, не помеченные приватными |
| I3: заголовки сессий | есть (при разрешённом тексте) | нет | нет |
