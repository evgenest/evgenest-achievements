# 03. Collector

> **Для кого:** тот, кто пишет collector (I1–I4). Пользователю форка достаточно разделов «Команды», «Конфиг» и
> «Режимы и значения по умолчанию».
> **Что здесь решает владелец:** ничего из общего списка. Свои решения — какой репозиторий с текстом, какой цифрами,
> какой не собирать — владелец принимает уже на машине командой `collector set`. Вопросы — в [общем README](../README.md).
> **Что просто к сведению:** всё остальное.

Продолжения: поиск репозиториев, вызовы git и строки загруженных документов — [03a-git-calls.md](03a-git-calls.md);
сессии Claude Code (I3) — [03b-sessions.md](03b-sessions.md).

## Принципы и раскладка

Collector — маленькая программа без зависимостей, которая между запусками ничего не помнит, кроме выбрасываемого кэша.

- TypeScript, среда запуска — **Bun**. Ядро — на `node:*` и глобальных `fetch`/WebCrypto, без `Bun.*` (проверяют
  тест-поиск и `types: ["node"]`): код тестируется существующим vitest под Node. Ноль зависимостей, git — через
  командную строку, `bun install` не нужен. Запуск под чистым Node не обещаем.
- Запуск из клона форка: `bun run collector <команда>`. Для расписания — **выделенный клон или worktree на закреплённом
  коммите** (позже — на теге `collector-vX.Y.Z`), а не рабочее дерево разработки: иначе cron каждый час исполняет то,
  что лежит на незаконченной ветке. `collectorVersion` берётся из `collector/version.ts`.
- Снимок — чистая функция от (состояние git, конфиг, список учтённого): журнала «что я уже отправлял» на машине нет.
  Каждый файл — одна забота; новое по сравнению с первой версией — `rules.ts`, `git/imported.ts`, команды `set`, `repos`.

```
collector/
  cli.ts · config.ts · rules.ts · version.ts   аргументы; config.json (атомарная запись), SHARED_FORGES;
                      resolveMode → режим; collectorVersion
  discover.ts · remote.ts · classify.ts   обход корней; remote → хост + путь (user:token@ отрезается сразу); класс:
                      github | declared | undeclared-host | no-remote | partial-clone | failed
                      (github — любой GitHub-remote, свой или чужой: до I5 пропускаются все)
  git/                commands.ts (разрешённые команды → argv) · exec.ts (без shell, окружение, таймаут) · log.ts
                      (git log + строгий разбор) · identity.ts · repo-id.ts · imported.ts (строки документов)
  sources/ · snapshot.ts · transport.ts   git-local, claude-code (I3, 03b); сборка снимка; единственный файл с fetch
  commands/ · test/   scan, push, set (I1); init, repos, doctor, schedule (I2); vitest на временных репозиториях
```

Общий контракт импортируется из `src/ingest/wire.ts` и `src/ingest/guard.ts`, вырезание секретов — из `src/secrets.ts`
(все без `Env`). Тест-поиск: `collector/**` и эти три файла импортируют только `node:*` и относительные модули.

## Команды

Уже в I1 машину можно настроить без правки JSON руками: `scan` показывает, `set` решает, `push` отправляет.

| Команда | Итерация | Что делает |
|---|---|---|
| `scan` | I1 | Таблица **режим / почему / коммиты / репозиторий / папка** и строка «сервер принимает текст: да \| нет, потому что …» (по проверочному запросу). «Почему»: личное правило, правило сервера, нет remote, сервер не объявлен, GitHub, неполный клон. `--json` — ровно тот снимок, что отправил бы `push`. `--explain <путь>` — почему коммитов нет: чужой e-mail (только число), вне окна, merge, режим `off`, **уже учтён** |
| `set <папка\|id> <text\|counters\|off>` | I1 | Пишет личное правило в `repos[]`. `id` — тот же номер, что `local/<id>` в отчёте: по отчёту видно, что править |
| `push` | I1 | Проверочный запрос → режимы → снимок → общий валидатор → отправка. `--dry-run` — напечатать байты и ничего не слать; `--force` — отправить, даже если ничего не изменилось. Ключа `--window-days` больше нет |
| `init` | I2 | Мастер: адрес Worker'а, токен скрытым вводом, проверочный запрос, **сначала серверы, потом репозитории** (ничего не отмечено заранее), ваши e-mail'ы; итог «уйдёт: N репозиториев, M коммитов, текст — у K» и строка расписания |
| `repos` | I2 | Та же таблица, что у `scan`, с выбором режима на месте |
| `doctor` | I2 | **Никогда не пишет.** Версия git (≥ 2.37; ≥ 2.45 для полной защиты), права файлов, проверочный запрос и причина простыми словами, почему текст не уходит; проблемы по репозиториям; `safe.directory=*`; расхождение часов; чувствительные файлы в git-дереве |
| `sessions forget [--all]` | I3 | Очистить кэш отметок промптов |
| `schedule` | I2 / I4 | I2: `print` — строки расписания с абсолютными путями. I4: `install \| uninstall \| status` для systemd и cron |

Как это выглядит (данные выдуманы):

```text
$ bun run collector scan
режим     почему                     коммиты  репозиторий                      папка
text      правило сервера                 40  <forge-host>/me/garden-sensors   ~/code/garden-sensors
text      личное правило                  12  <forge-host>/me/cli-tools        ~/code/cli-tools
counters  личное правило                   3  <forge-host>/team/shared-lib     ~/code/shared-lib
off       нет remote                       —  —                                ~/tmp/scratch
пропущен  GitHub — его собирает Worker     —  <owner>/shop-backend             ~/code/shop-backend

сервер принимает текст: да

$ bun run collector set ~/code/shared-lib off
shared-lib: counters → off (правило записано в config.json; подействует со следующей отправки)
```

Если Worker текст не принимает, последняя строка таблицы называет причину: «сервер принимает текст: нет, потому что
репозиторий отчётов публичный»; все строки `text` при этом уйдут цифрами.

- Конфиг пишут только интерактивные команды (`set`, `init`, `repos`; `scan` лишь обновляет устаревшие `remote` и `path` в
  существующих записях). Запуск по расписанию конфиг **не пишет никогда**. Запись атомарная (временный файл и
  переименование), незнакомые ключи и их порядок сохраняются; невалидный JSON — отказ без перезаписи.
- Флаги: `--config <путь>`, `--quiet`, `--verbose` (только счётчики, никогда не содержимое).
- Ответы на `push`. 200 или «ничего не изменилось» → выход 0. 400 / 403 / 409 / 413 → **ненулевой выход и строка в
  stderr даже при `--quiet`**, без повтора: иначе отключённая машина невидима. 429 / 503 / нет сети, в том числе на
  проверочном запросе → выход 0, **снимок не отправляется**, повтор следующим запуском. 403 / 503 без заголовка
  `X-Ingest` → «блокирует защита зоны Cloudflare, а не Worker». 404 → функция выключена или не тот адрес.

## Порядок `push`

Каждый запуск начинается с проверочного запроса; не удался он — не отправляется ничего.

- Шаги: (1) проверочный запрос `GET /ingest/v1/<machineId>` — можно ли текст и что уже учтено
  ([01](01-architecture.md#проверочный-запрос)); (2) `resolveMode` по каждому репозиторию — по `off` `git log` **не
  запускается**, для `counters` в формате нет `%s` и `%b`; (3) по списку учтённого: Worker знает оба ключа коммита → не
  слать, один → слать без текста, ни одного → как обычно, старше границы `from` → не слать ([07](07-selection.md));
  (4) снимок → общий валидатор → `PUT` с меткой `X-Accounted-Through`.
- Отправка пропускается, если хеш от (`repos`, `sessions`, `through`) не изменился и прошлая моложе 24 ч. После любого
  прогона `through` меняется, поэтому ближайший запуск перезаливает снимок — так учтённый текст уходит из KV в пределах
  часа. Снимок — полная замена: смена режима на машине или политики на Worker'е действует со следующей отправки.
- Снимок больше `bodyBytes` (2 МиБ) сжимается предсказуемо: сначала отбрасываются `message` (старые первыми), затем
  `headline`; коммиты, даты и числа не отбрасываются никогда; не помогло — ошибка без отправки. Счётчик — `textDropped`.

## Конфиг

Три основных ключа и четыре необязательных вместо прежних тринадцати; типичному пользователю хватает двух строк. Файл —
`${XDG_CONFIG_HOME:-~/.config}/achievements-collector/config.json` (Windows: `%APPDATA%\achievements-collector\`).

```ts
// collector/config.ts
type Mode = "text" | "counters" | "off";
interface CollectorConfig {
  endpoint: string;               // основной: адрес Worker'а; только https:// (кроме localhost)
  hosts?: Record<string, Mode>;   // основной: "<хост>" или "<хост>/<пространство-имён>" → режим по умолчанию оттуда
  repos?: RepoRule[];             // основной: личные правила; пишут команды set / init / repos
  roots?: string[];               // где искать; по умолчанию ["~"]
  noRemote?: "off" | "counters";  // репозитории без remote; по умолчанию "off"; text — только личным правилом
  emails?: string[];              // в дополнение к git config user.email
  sessions?: boolean;             // I3: сессии Claude Code; по умолчанию false
}
interface RepoRule {
  mode: Mode;
  label: string;      // для человека: "<хост>/<пространство>/<репозиторий>" или "~/<папка>"
  root?: string;      // 12 hex наименьшего корневого коммита; у клона с обрезанной историей (shallow) его нет
  remote?: string;    // нормализованный хост/путь на момент решения
  path?: string;      // папка на момент решения (с ~)
  decidedAt: string;  // дата решения
}
```

```json
{ "endpoint": "https://<worker-url>", "hosts": { "<forge-host>": "counters" } }
{ "endpoint": "https://<worker-url>", "hosts": { "<forge-host>": "text" }, "sessions": true }
```

Первая строка — посторонний пользователь, вторая — весь конфиг владельца (личный сервер, позже сессии). Что убрано:
`share` (общий и на сервер) → режим репозитория, «текст, только когда это безопасно» встроено в сам `text`; `include`,
`exclude` → личные правила `repos[]`; `includeNoRemote` → `noRemote`; `maxDepth` → константа 6; `notBefore` и
`push --window-days` → ничем (лишнее переводится в `off` до первой отправки, потерянные недели закрывают корректирующие
отчёты); `githubOwners` → до I5 пропускаются **все** репозитории с GitHub-remote; `sessionsScope` и уровни сессий → галочка.

## Режимы и значения по умолчанию

Режим определяет чистая функция `resolveMode` в `collector/rules.ts`; без решения человека получаются только цифры.

1. GitHub-репозиторий или неполный клон — не собирается вовсе; в таблице `scan` у него стоит причина «GitHub» или
   «неполный клон». Это не режим: правилами его не изменить (в I1–I4), и к значению `skip` переменной `PRIVATE_REPOS`
   он отношения не имеет.
2. **Запрет.** Личные правила с режимом `off` или `counters`, у которых совпал `root` **или** `remote` **или** `path`;
   берётся самое строгое (`off` строже `counters`).
3. **Разрешение.** Личное правило `text` срабатывает, если совпал `root` **и** ещё `remote` или `path`. Правило без
   `root` (обрезанная история) режим `text` не даёт.
4. Иначе — самый длинный совпавший ключ из `hosts` для **каждого** remote. Есть remote вне `hosts` → `off` и счётчик
   `reposSkippedHost`. Несколько remote → самый строгий режим. Нет remote → `noRemote`, по умолчанию `off`.

- По сети идёт `share: "text"`, только если режим `text` **и** проверочный запрос ответил `text.allowed: true`; иначе —
  `"counters"` с `name: null` и счётчиком `textDowngraded`. Режим `off` в передаваемые данные не попадает вовсе.
- `reposUndecided` — сколько репозиториев собрано по правилу сервера без личного решения. Сноска отчёта подсказывает:
  «N репозиториев переданы только цифрами, из них M без вашего решения — `collector scan`».
- **Вопрос `init` про личный сервер.** Про каждый найденный сервер `init` спрашивает прямо: «Это ваш личный сервер, где
  всё ваше?» Да → `"<хост>": "text"`, весь сервер с текстом одной строкой. Нет или не уверены → `counters`.
- **Общие площадки** (константа `SHARED_FORGES` — публичные SaaS-хостинги git): вопрос не задаётся, текст целому
  серверу запрещён, **голый хост без пространства имён — ошибка конфига**; `init` группирует найденное по «хост +
  первый сегмент пути». Иначе, объявив общий хост ради личных репозиториев, можно впустить пространство имён
  работодателя. *Принятое допущение:* пространству имён на общей площадке `init` предлагает только `counters`; `text`
  там ставится по одному репозиторию командой `set`.

## Привязка правила к репозиторию

Правило хранит три признака — `root`, `remote`, `path`; запрет липкий (хватает любого из трёх), разрешение узкое (нужен
`root` и ещё один).

| Что произошло | Что будет |
|---|---|
| Перенесли папку **или** сменили адрес remote | Правило находится: `off` остаётся `off`, `text` остаётся `text`; `scan` и `set` обновляют устаревший признак в записи |
| Переименовали на сервере **и** перенесли папку разом | Запрет остаётся (совпал `root`). `text` не срабатывает — репозиторий идёт по правилу сервера, `scan` и `push` пишут: «правило text для `<label>` не совпало — подтвердите: `collector set <папка> text`» |
| Новый проект из шаблона с тем же первым коммитом | Запрет наследуется (безопасная сторона; `scan` показывает причину), `text` — нет |
| Клон с обрезанной историей | `root` нет: запрет работает по `remote` или `path`, `text` не даётся |
| Тот же репозиторий на второй машине | Правила у каждой машины свои; на Worker'е побеждает самое строгое, а `off` ставится на каждой машине ([08](08-threat-model.md)) |

Почему так: пути и имена по сети не ходят, поэтому привязка живёт только на машине, а первый коммит не меняется при
переносе папки, смене адреса, переименовании на сервере и повторном клонировании. Асимметрия нужна из-за общих корней:
проект из шаблона не должен унаследовать `text`, а репозиторий, переведённый в `off`, обязан остаться `off` при любых
перемещениях. Отклонено: ключ — путь remote (переименование снимает `off`); ключ — папка (теряется при переносе);
«самое строгое из всех совпавших» (нельзя выразить «сервер цифрами, один проект текстом»).

## Каталог состояния и чувствительные файлы

Всё чувствительное лежит не рядом с конфигом, а в каталоге состояния: `~/.config` слишком часто попадает в репозиторий
с личными настройками (dotfiles). Каталог — `${XDG_STATE_HOME:-~/.local/state}/achievements-collector/` (Windows:
`%LOCALAPPDATA%`), права 0700, у файлов 0600.

- `credentials` — токен приёма (другой способ — переменная `ACHIEVEMENTS_INGEST_TOKEN`); `machine-id` — `m-<8 hex>`,
  создаётся при первой отправке; `last-push.json` — хеш содержимого, время и последний ответ Worker'а, единственный
  выбрасываемый кэш; `prompt-cache.json` (I3) — увиденные минутные отметки промптов, его удаление теряет неучтённые
  минуты удалённых сессий; `aliases.json` — только если когда-нибудь появится словарь замен имён (A1).
- **Не синхронизировать** каталог между машинами: общий `machine-id` заставит их каждый час затирать снимки друг друга.
- `doctor`: любой из этих файлов внутри git-дерева — **ошибка**; неверные права — ошибка.
- `config.json` остаётся в `~/.config`, но теперь хранит метки и пути репозиториев, в том числе приватных: конфиг внутри
  git-дерева — заметное предупреждение. *Принятое допущение:* `doctor` печатает короткий отпечаток набора правил, чтобы
  сравнить две машины, не показывая сами правила.

## E-mail'ы автора, расписание, путь нового пользователя

Чужие коммиты не отправляются никогда; запускать `push` можно часто: повтор ничего не ломает (каждая отправка
заменяет предыдущую целиком) и стоит дёшево.

- **E-mail'ы:** объединение `git config --global user.email`, локальных `user.email` **собираемых** репозиториев и
  `emails[]`. `init` показывает самые частые e-mail'ы авторов со счётчиками — пользователь отмечает свои.
- **Расписание.** I1 — одна строка cron: `17 * * * * <abs-bun> run <abs-clone>/collector/cli.ts push --quiet` (пути
  абсолютные: в cron `PATH` обычно не содержит `~/.bun/bin`). I2 — `schedule print`: systemd user timer
  (`OnCalendar=hourly`, `Persistent=true`, `RandomizedDelaySec=300`; на сервере — `loginctl enable-linger <user>`),
  crontab, launchd, Task Scheduler (последние два — «проверено сообществом»). I4 — `schedule install`. На macOS cron и
  launchd не читают защищённые папки (`Documents`, `Desktop`); WSL и Windows-установка — две разные машины.
- **Путь нового пользователя (после I2):** обновить форк и задеплоить Worker → создать токен
  ([05](05-operations.md#токен-создание-и-ротация)) → клон на закреплённом коммите → `bun run collector init` →
  `push --dry-run`, посмотреть, что уйдёт, → `push` → вставить строку расписания. Отдельного шага «хочу названия и
  сводки» больше нет: это отметка `text` в `init`, а чего не хватает на Worker'е, скажет `doctor`. В I1 мастера нет:
  `endpoint` и `hosts` пишутся руками (две строки), остальное — `scan` и `set`.
