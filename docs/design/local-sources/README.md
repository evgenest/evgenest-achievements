## Главное за минуту

Работа вне GitHub попадёт в тот же недельный отчёт; с машины уходит только то, чего Worker ещё не учёл, а
текст коммитов — только когда это безопасно.

- **Зачем.** Отчёт видит только GitHub. Теряются репозитории, чей единственный сервер — свой git-сервер
  (Forgejo, Gitea, GitLab; в том числе в приватной сети, куда Worker не достучится), репозитории без
  remote и работа в сессиях Claude Code. Измерено: три корректирующих отчёта за недели №6–№8 нашли больше
  ста коммитов, которых основные отчёты не видели; почти половина человеческих промптов в Claude Code за
  неделю — в репозиториях вне GitHub.
- **Как.** На машине работает маленькая программа-сборщик (collector: TypeScript, Bun, ноль зависимостей).
  Раз в час она читает `git log` и отправляет Worker'у снимок: `PUT /ingest/v1/<machineId>`. Worker кладёт
  снимок в KV как есть, а в недельном прогоне сам выбирает события своего окна, отсеивает дубли и вливает
  их в неделю **до** политики приватности. Дальше работает весь существующий конвейер.
- **Один отчёт.** После выхода I1 на неделю выходит один общий отчёт: GitHub, локальные репозитории и всё,
  что отслеживается по файлу настроек. Часы считаются на одной общей шкале времени.
- **Только неучтённое.** Worker публикует список коротких хешей уже учтённых коммитов; collector
  присылает лишь то, чего в списке нет. Решает по-прежнему журнал учтённого (ledger) на Worker'е, список —
  подсказка для экономии: [07-selection.md](07-selection.md).
- **KV — транзитный буфер.** Текст коммита лежит в KV, пока коммит не учтён (и ещё один прогон, если принят
  «грейс»); срок жизни снимка — 9 дней вместо 45. Источник истины для текста — git на машине.
- **Настройка — одно решение на репозиторий:** с описанием (`text`) / только цифры (`counters`) / не
  собирать (`off`).
- **Workers Free.** Проверено на Free: недельный прогон 40–110 мс процессора проходит; Cloudflare этого не
  гарантирует; для больших объёмов надёжнее платный тариф. Замеры — в [05-operations.md](05-operations.md).
- **Потерянные недели** не возвращаются переписыванием старых отчётов: для них выходят отдельные
  корректирующие отчёты `<день>_local.md`, каждую пятницу до выхода I1.
- **Форки.** Пока не задан `INGEST_TOKEN`, поведение не меняется.

## Что получит владелец, а что — посторонний пользователь

Владелец одной строкой включает «весь свой сервер с текстом»; у постороннего без его решения уходят только
цифры.

| | Владелец (личный сервер, где всё своё) | Посторонний, настройки по умолчанию |
|---|---|---|
| Конфиг collector'а | адрес Worker'а, свой сервер в режиме `text`, позже — `sessions: true` | адрес Worker'а, сервер в режиме `counters` |
| Что уходит с машины | имя репозитория, тексты своих коммитов, даты, число строк | даты и число строк; без имён и текстов |
| Что в отчёте | проект под своим именем и со сводкой, в общей таблице | «приватный проект»: коммиты, строки, часы, ачивки |
| Условия для текста | оба выполнены; Worker проверяет это сам в каждом прогоне ([02](02-privacy.md#два-условия-для-текста)) | текст не уходит, пока пользователь сам не поставит `text` и Worker не подтвердит оба условия |
| Репозитории без remote | `off`; нужные включаются по одному: `collector set <папка> <режим>` | то же |

```json
{ "endpoint": "https://<worker-url>", "hosts": { "<forge-host>": "text" }, "sessions": true }
```

Это весь конфиг владельца. У постороннего на месте `"text"` стоит `"counters"`, а `sessions` нет. `init`
про каждый найденный сервер спрашивает прямо: «это ваш личный сервер, где всё ваше?» — и только тогда
пишет `text`. Для общих площадок (SaaS) текст целому серверу запрещён: нужен вид
`<хост>/<пространство-имён>`, голый хост — ошибка конфига. Таблица «режим → что уходит → что в отчёте» — в
[02-privacy.md](02-privacy.md); ключи конфига и команды — в [03-collector.md](03-collector.md).

## Зафиксированные принципы

Девять правил, которые не пересматриваются от итерации к итерации; общие принципы P1–P9 всего roadmap — в
[общем README](../README.md).

1. Собирает локальная программа, отчёт строит Worker (модель, приватность, state, Telegram).
2. **Один общий отчёт на неделю.** Корректирующие отчёты — только для недель, вышедших до I1; после I1 они не
   обещаны и как аварийное средство.
3. По сети идут **сырые датированные события**, не недельные итоги. Окно `[since, until)` определяет
   только Worker — иначе ломаются догоняющий прогон (до 4 недель), `?date=` и откат `DELETE /state/latest`.
4. **Отправляется только то, чего Worker ещё не учёл.** Снимок — чистая функция от (состояние git, список
   учтённого): каждая отправка заменяет его целиком, повтор ничего не ломает, журнала «что я уже отправлял» на
   машине нет.
5. **KV — транзитный буфер.** Сырьё не хранится: после попадания в отчёт текст коммитов остаётся только
   в отчёте. Источник истины для текста — git на машине, долгая память проекта — готовые отчёты.
6. Политика приватности и вырезание секретов авторитетны на Worker'е; при сомнении — скрыть. Публичным
   считается только то, что Worker сам прочитал у хостинга; текст для публичного показа с машины не берётся.
7. Проект публичный: пока не задан `INGEST_TOKEN`, поведение не меняется. Исключения — явно названные
   исправления I0; они ведутся одним списком «Изменения поведения» в README проекта.
8. Сбой новой части ухудшает отчёт (меньше локальных коммитов, сноска), но не роняет его.
9. Один кроссплатформенный скрипт вместо скриптов под каждую ОС; от ОС зависит только расписание.

## Журнал решений

Старые строки сохранены; то, что заменено или уточнено решениями 2026-09-19, помечено в самой строке.

| Дата | Решение | Почему |
|---|---|---|
| 2026-09-18 | Локальный collector отправляет, Worker строит отчёт | Worker не видит ни приватную сеть, ни диск; у Worker'а уже есть приватность, защита данных для модели, state, откат |
| 2026-09-18 | Транспорт: `PUT /ingest/v1/<machineId>` → KV, один ключ на машину, перезапись | Повтор ничего не ломает (идемпотентно); ноль внешних запросов; очередь не годится (сообщение ≤ 128 КБ). Git как транспорт отклонён: приватные данные навсегда в истории GitHub, катастрофа при публичном репозитории отчётов |
| 2026-09-18 | Сырые события + окно на Worker'е. *(Заменено 2026-09-19: «снимок держит всё окно 35 дней и живёт 45 дней» → «только неучтённое, срок 9 дней».)* | Откат, `?date=`, догоняющий прогон пересобирают неделю из тех же данных |
| 2026-09-18 | Приём не разбирает тело; проверка формата — в прогоне и в collector'е (общий рукописный валидатор) | Маршрут под токеном с рабочей машины остаётся дешёвым и ограниченным. Валидатор в ~10 раз дешевле zod и не тянет зависимость |
| 2026-09-18 | Выбор событий — журнал учтённого внутри append-only `AppState`; **GitHub-коммиты прогона тоже пишутся в журнал** | Отметка «до какого места дошли» на машину задваивает неделю при двух машинах и теряет опоздавшее. Без GitHub-записей зеркало задваивалось бы неделей позже |
| 2026-09-18 | Дубли: SHA глобально, затем `K = секунда автора + additions + deletions` в пределах репозитория | Только SHA: rebase-копии задваиваются. Только «секунда автора»: теряет 5,4% реальных коммитов. `K` дал ровно «SHA минус rebase-копии» |
| 2026-09-18 | Лимит — один, на прогон, **старые первыми**, растёт с длиной догоняющего прогона; не влезшее откладывается, сгоревшее считается | «Новые первыми» навсегда теряет самые старые отложенные коммиты (модель: 49 из 196) |

### Принятые допущения (дёшево изменить)

Шесть мелких решений приняты без владельца; любое из них легко поменять.

- Один общий `INGEST_TOKEN`; токены на машину — позже, без изменения формата передачи.
- Длина коротких хешей — 10 и 12 hex-символов (вероятность тихой потери коммита ≈ 1e-8). Менять формат
  журнала после первого боевого прогона дорого, поэтому решить нужно до него.
- I3 (сессии) раньше I4 (установка расписания): владельцу ценнее сессии.
- Запуск из клона; npm-пакет — только если попросят.
- Неделя только с сессиями, без коммитов, активной не считается (серию недель не трогаем).
- Порядок репозиториев в отчёте при включённой функции — по дате последнего коммита.

## Стыковка с записью недели, трендами и ретроспективами

Локальные источники ничего не хранят «для трендов»: всё долговечное уходит в запись недели в момент
сборки отчёта.

- I1 заполняет в записи недели поле `local` (учтено, опоздавших, отложено, сгорело) и добавляет `"local"`
  в `sources`; I3 заполняет `ai`. Схема — в [../week-record/01-schema.md](../week-record/01-schema.md).
- Появление источника `local` рвёт ряд сравнения один раз, со сноской «с недели #N учитываются локальные
  источники» — иначе первая неделя I1 выглядела бы ложным рекордом. Появление `sessions` ряд не рвёт: время в
  паре с ИИ в часы не входит ([схема](../week-record/01-schema.md#неровные-недели-и-разрыв-ряда)).
- Недели до I1 живут двумя файлами (основной и `<день>_local.md`). Недельный мини-график их не видит —
  они на нём занижены; ретроспектива складывает оба файла как одну неделю работы.
- R1 (восстановление записей прошлых недель) делается **строго до** I1-T: он добавляет в цепочку state
  снимок, который не является прогоном, а на линейности цепочки стоит проверка полноты снимка.
