# 02. Приватность: что уходит с машины и что попадает в отчёт

> **Для кого:** владелец и любой пользователь форка (своей копии проекта). Код знать не нужно.
> **Что здесь решает владелец:** режим каждого репозитория на своей машине — и три пункта общего списка: №2 (служебные
> хвосты коммитов), №3 (трассы Cloudflare), №4 («грейс»). Сами вопросы и рекомендации — только в
> [общем README](../README.md).
> **Что просто к сведению:** всё остальное. Подробности для разработчика вынесены: секреты и угрозы —
> [08-threat-model.md](08-threat-model.md), публичные проекты — [09-public-visibility.md](09-public-visibility.md).

## Главное за минуту

Без вашего решения с машины уходят только цифры; текст — отдельное решение на каждый репозиторий, и даже тогда Worker
пропускает его, только убедившись, что отчёты приватные.

- Про каждый репозиторий принимается **одно решение**: с описанием (`text`), только цифры (`counters`), не собирать (`off`).
- «Объявить сервер» — вписать адрес своего git-сервера в настройки collector'а (ключ `hosts`). Пока про репозиторий нет
  решения: с объявленного сервера он идёт как `counters`; с сервера, который вы не объявляли, и вовсе без сервера —
  `off`, то есть не собирается.
- Клоны GitHub-репозиториев collector пропускает: их и так собирает Worker через GitHub.
- Режим одного репозитория меняется одной командой: `collector set <папка> text|counters|off`.
- Ошибка «цифры вместо текста» обратима: сменили режим, сняли последний прогон, собрали неделю заново. Утёкший текст
  отозвать нельзя. Поэтому по умолчанию — цифры.
- Уходят только **ваши** коммиты (по вашим e-mail'ам). Чужие — никогда.
- Текст в KV (хранилище Cloudflare «ключ → значение») — проездом: пока коммит не попал в отчёт и ещё один прогон после.
- Пока на Worker'е не задан `INGEST_TOKEN`, ничего из этого не включено и поведение форка не меняется.

## Режим → что уходит → что в отчёте

Режим задаётся на машине командой `collector set <папка> <режим>`; строже его может сделать Worker, мягче — никто.

| Режим | Что уходит с машины | Что появляется в отчёте |
|---|---|---|
| `text` — с описанием | имя репозитория; заголовки и тексты ваших коммитов (секреты вырезаны, длинное обрезано); даты коммитов; число строк | проект под своим именем и рассказ о сделанном — **если выполнены оба условия ниже**. Иначе — как `counters`, а сноска отчёта называет причину |
| `counters` — только цифры | даты коммитов и число строк. Имени и текстов нет. Технические метки: короткий номер репозитория (хеш) и SHA коммитов | строка без имени: `local/<номер>` при `PRIVATE_REPOS=full`, «приватный проект» при `redact`, ничего при `skip`. Коммиты, строки, часы, ачивки считаются |
| `off` — не собирать | ничего: по репозиторию даже не запускается `git log`; время сессий Claude Code в нём тоже не уходит | ничего, нигде — ни в отчёте, ни в записи недели, ни в трендах |

- Вместе со снимком всегда уходят: случайный номер машины (`m-<8 hex>`), версия collector'а и счётчики диагностики (числа).
- «Только цифры» — это псевдонимы, а не анонимность: коммит публичного проекта находится поиском по SHA, а секундные
  даты вместе с размерами коммитов — отпечаток активности. Чего не должно быть видно совсем — ставьте `off`.
- Строки загруженных извне документов (PDF, письма, офисные файлы) collector отделяет сам; имена файлов при этом
  остаются на машине — [03a-git-calls.md](03a-git-calls.md#строки-загруженных-документов).

## Два условия для текста

Текст репозитория `text` попадает в отчёт, только когда выполнены оба условия, и проверяет их сам Worker.

1. На Worker'е стоит `PRIVATE_REPOS=full`.
2. Репозиторий отчётов **подтверждённо приватный**: Worker спрашивает об этом GitHub сам — при проверочном запросе
   collector'а (ответ помнится час) и заново в каждом недельном прогоне.

- Перед каждой отправкой collector делает проверочный запрос. Условие не выполнено или проверить не удалось — текст
  **не покидает машину**, уходят цифры, а `scan`, `doctor` и `push` называют причину одной фразой: режим не `full`;
  репозиторий отчётов публичный; проверить не удалось.
- Worker со своей стороны отбрасывает текст, даже если его прислали («при сомнении — скрыть»).
- Кто увидит текст в режиме `text`: репозиторий отчётов, провайдер модели и ваш Telegram-чат. Приватность чата Worker
  **не проверяет**: если это группа, имена и факты увидят все участники. Уже вышедшие отчёты не отзываются, если
  репозиторий отчётов позже открыть.
- К сведению: владелец для своего сервера выбрал режим `text` для всех репозиториев. Переключатель на репозиторий
  остаётся для остальных пользователей.

## Не уходит никогда

Ни в одном режиме по сети не идут: пути и имена папок, рабочая папка сессии, сетевое имя машины, имя пользователя ОС,
e-mail'ы, имена веток, адреса серверов (remote), имена файлов, содержимое файлов и диффы, номера сессий, текст ваших
промптов и ответов модели, вывод инструментов.

- Команды `scan`, `init`, `doctor` показывают пути и серверы **на вашем экране** — иначе ими нельзя пользоваться. В сеть
  и в журнал расписания это не попадает; `push --dry-run` печатает ровно те байты, что уйдут.
- Единственное исключение — позднее и по желанию (I6): заявка «этот репозиторий публичный» для других хостингов несёт
  путь репозитория, на ваш же Worker, и только если Worker сам назвал этот хостинг —
  [09-public-visibility.md](09-public-visibility.md).

## Сколько текст живёт в KV

Текст коммита лежит в KV, пока коммит не учтён в отчёте, и ещё один прогон после («грейс» — пункт №4 общего списка).

- **Машина работает:** текст учтённой недели исчезает при первой отправке после **следующего** прогона — в пределах
  часа после него; на практике это около недели после отчёта.
- **Машина замолчала или `INGEST_TOKEN` убрали:** не позже 9 суток после её последней отправки — это срок жизни снимка.
- **Нужно сразу:** `DELETE /ingest/v1/<machineId>` — [05-operations.md](05-operations.md).
- **Если на №4 ответить «без грейса»:** текст уходит при первой отправке после отчёта, но после каждого отката нужен
  `collector push`, а при спящей машине честно пересобрать неделю нельзя.

Зачем отсрочка: привычное «снять прогон, сменить модель, собрать ту же неделю заново» работает сразу, без ожидания
отправки. После отчёта текст остаётся только в самом отчёте (и у получателей выше); источник истины для текста — git на
машине. Надолго на Worker'е остаются лишь короткие хеши учтённых коммитов (журнал учтённого), не текст.

## Сессии Claude Code: одно правило

Одна галочка `sessions: true` (по умолчанию выключено, появится в I3); заголовок сессии подчиняется режиму её репозитория.

- Уходят отметки времени ваших промптов, округлённые до минуты, и ключ проекта. В отчёте — отдельная строка «время в
  паре с ИИ»; к часам она не прибавляется.
- Заголовок сессии — пересказ вашего промпта моделью, в нём бывают имена клиентов. Он уходит, только если репозиторий
  сессии в режиме `text`, Worker разрешил текст и в сессии есть ваш промпт не раньше начала последней отчитанной недели
  (так при грейсе; без грейса — после последнего отчёта). Иначе — только время и проект.
- Сессия в репозитории `off` (в том числе с необъявленного сервера) или вне любого репозитория не уходит вовсе —
  ни время, ни проект.

## Словарик

- **Проверочный запрос** — `GET`, которым collector перед отправкой спрашивает Worker, можно ли слать текст и что уже учтено.
- **«При сомнении — скрыть»** — любой сбой проверки считается отказом: лучше блёклая строка, чем утёкший текст.
- **Журнал учтённого (ledger)** — короткие хеши уже посчитанных коммитов внутри state; по ним коммит не считается дважды.
- **Снимок** — один JSON с событиями одной машины, один ключ в KV; каждая отправка заменяет его целиком.
