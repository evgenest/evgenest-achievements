# 09. Когда локальная работа считается публичной

> **Для кого:** разработчик итераций I5 и I6; пользователь форка с публичным репозиторием отчётов, которому важно,
> какие проекты покажутся под своим именем.
> **Что здесь решает владелец:** ничего нового. Сужение правила для GitHub и перенос других хостингов в позднюю
> необязательную итерацию I6 уже приняты (журнал решений — в [README.md](README.md)); вопросы — только в
> [общем README](../README.md).
> **Что просто к сведению:** всё. В итерациях I1–I4 этот документ **ничего не меняет**: всё локальное приватно.

## Главное за минуту

Публичным считается только то, что Worker сам прочитал у хостинга; имя и текст для публичного показа берутся из ответа
хостинга и никогда — с машины.

- Сегодня и до I5 любой локальный репозиторий приватный: его судьбу решает одна ручка `PRIVATE_REPOS`.
- Исключение первое (I5): коммит, который Worker нашёл в **ветке по умолчанию вашего публичного GitHub-репозитория**.
- Исключение второе (I6, по желанию): коммит, который Worker нашёл в **анонимно читаемом списке коммитов** на хостинге
  из своей переменной `PUBLIC_HOSTS`.
- С машины приходит только заявка «проверь, не публично ли это». Заявка ничего не доказывает и ничего не раскрывает.
- Любой сбой проверки → в этом прогоне приватно. Отчёт не падает, в сноске — счётчик `publicUnverified`.
- Уже сейчас (I1) резервируются четыре вещи, чтобы потом не понадобился второй формат передачи.

## Почему нельзя решать «на репозиторий»

Правило «у репозитория есть публичный GitHub-remote — значит, он публичный» раскрывает приватный текст; это проверено
на семи тестовых репозиториях.

| Случай | Что утекло бы |
|---|---|
| Незапушенная работа в клоне публичного репозитория | Текст коммитов, которых на GitHub ещё нет |
| Второй remote — приватный | Работа, живущая только на приватном сервере |
| Приватный форк публичного проекта | Вся приватная ветка разработки |
| Репозиторий сделали приватным после клонирования | Всё: клон «помнит» старый адрес |
| Подделанные ссылки отслеживания (`refs/remotes/*`) | Что угодно: ссылки — обычные файлы на диске |

Отсюда принятое правило: решение принимается **по коммиту**, проверяет его Worker своим токеном, при сомнении — скрыть.

## Правило для GitHub (I5)

Коммит публичен, только если выполнены все три условия; первая версия правила была шире, и её сузила найденная дыра.

1. Заявка `gh:<хеш owner/name>` совпала с репозиторием из **собственного** списка Worker'а (`/user/repos` уже загружен —
   0 запросов), и этот репозиторий не приватный.
2. Одним запросом GraphQL получено `aheadBy === 0`: коммит достижим из ветки по умолчанию **этого самого** репозитория.
3. `author.user.login === GITHUB_USER`.

Имя, текст, даты, статистика и ссылка берутся из ответа GitHub. Всё остальное приватно.

**Дыра, из-за которой правило сужено** (проверено живым запросом). Проверка «коммит существует в репозитории» —
`repository(owner, name).object(oid)` — находит и коммит, которого в репозитории нет: он лежит в **чужом форке**, а сеть
форков у GitHub общая. Поле `author.user.login` при этом подделывается: достаточно указать e-mail владельца в авторе
коммита. Известный поддельный коммит в чужом публичном репозитории вернулся как коммит владельца; сравнение с веткой по
умолчанию дало для него `DIVERGED`, `aheadBy = 2`, а для настоящего — `BEHIND`, `aheadBy = 0`. С точки зрения
приватности первая проверка честна (текст и правда читается анонимно), с точки зрения подлинности — нет: держатель
утёкшего `INGEST_TOKEN` форкнул бы публичный репозиторий владельца, запушил коммит с любым текстом и вписал бы его в
отчёт, в том числе публичный.

```graphql
repository(owner: "<owner>", name: "<repo>") {
  isPrivate
  defaultBranchRef { c0: compare(headRef: "<sha>") { aheadBy } }        # достижим ли из ветки по умолчанию
  o0: object(oid: "<sha>") { ... on Commit { messageHeadline message authoredDate committedDate
                                              additions deletions url author { user { login } } } }
}   # c1/o1, c2/o2 … — по паре на каждый SHA, всё в ОДНОМ запросе
```

| Вопрос | Ответ |
|---|---|
| Сколько это стоит | **Измерено:** 300 сравнений и 300 объектов с текстом — 1 запрос, 1 единица лимита GraphQL, около 180 КБ, около 10 с. Обычная неделя — 1–2 с |
| Сколько SHA за прогон | Не больше 300, старые первыми; лишнее остаётся приватным |
| Что с коммитами, которые Worker уже собрал с GitHub сам | Считаются дублем: побеждает копия с GitHub |
| Как делится репозиторий | Публичная часть вливается в строку GitHub-репозитория под настоящим именем; остаток идёт как `local/<id>` |
| Цена узкого правила | Публичные коммиты в ещё не слитых ветках показываются как приватные. Это сознательная плата за подлинность |
| Что отклонено | Только `object(oid)` — подделывается. Перечисление всех веток — **проверено:** сортировка `TAG_COMMIT_DATE` по свежести не сортирует, у репозитория с 254 ветками первые 20 оказались старыми. REST-запрос на каждый коммит — 1 внешний запрос на коммит при лимите 50. Имя ветки в заявке — имена веток по сети не ходят |

Нынешний `graphql()` бросает исключение при любой ошибке в ответе (`src/github.ts:35-37`), поэтому проверке нужен свой
терпимый вызов: ошибка по одному репозиторию делает приватным только его. Вместе с I5 выходит «незапушенная работа в
GitHub-репозиториях»: до I5 collector пропускает все репозитории с GitHub-remote.

## Другие хостинги (I6, по желанию)

Принцип тот же — «публично только то, что Worker сам прочитал без авторизации», — и он безопасен только при четырёх
условиях.

| # | Условие | Зачем |
|---|---|---|
| 1 | Запрос **без единого заголовка авторизации**, без следования перенаправлениям (3xx = «не подтверждено»), только `https`, без порта и без IP-адреса вместо имени, таймаут 5 с, ответ не больше 512 КБ | Иначе «прочитал Worker» не значит «прочитает любой»; перенаправление — способ увести запрос на чужой адрес, и каждое считается отдельным внешним запросом |
| 2 | Worker ходит только на хосты и пространства имён из **своей** переменной `PUBLIC_HOSTS`; запись без пространства имён отклоняется. Заявка с машины — лишь подсказка | Иначе держатель токена заставил бы Worker ходить по произвольным адресам |
| 3 | Запрашивается **список коммитов** репозитория, а не отдельный коммит и не список ссылок. Публичны те коммиты с машины, чей SHA есть в списке; текст — из списка | Список ветки доказывает достижимость по построению: трюк с форком не проходит |
| 4 | Жёсткий бюджет: 6 запросов на прогон, не больше 2 страниц на репозиторий, первыми идут репозитории с большим числом коммитов | Проверка не должна отнимать внешние запросы у основной работы |

```
PUBLIC_HOSTS="<forge-host>/<namespace>=forgejo,<gitlab-host>/<namespace>=gitlab"     # обычная переменная, не секрет
Forgejo/Gitea: GET /api/v1/repos/<owner>/<repo>/commits?limit=50&stat=false&verification=false&files=false
GitLab:        GET /api/v4/projects/<ns%2Frepo>/repository/commits?all=true&since=<начало окна>&per_page=100
```

- **Проверено** анонимными запросами к публичным проектам: оба API отвечают 200 с текстом коммитов, 126–158 КБ на
  страницу, 404 на приватное и несуществующее. Forgejo отдаёт ветку по умолчанию, по 50; GitLab — все ветки, по 100.
- **Не проверено:** отвечает ли выбранный хостинг адресам Cloudflare. Защита от ботов может их резать — тогда функция
  тихо не срабатывает, но ничего не раскрывает. Замер с настоящего Worker'а входит в приёмку C6.
- В списках этих хостингов нет статистики строк: `additions` и `deletions` берутся из снимка (на приватность это не
  влияет), текст и имя — только из ответа хостинга.
- «Читается анонимно» не значит «задумано публичным»: случайно открытый репозиторий на объявленном хостинге попадёт в
  отчёт с текстом. Смягчение: хостинг объявляет только владелец Worker'а, а заявка идёт только для репозиториев в
  режиме `text`.
- Владельцу это сегодня ничего не даёт: его git-сервер в приватной сети, Worker до него не достанет, и все репозитории
  на нём приватные. Это функция для других пользователей, которую владелец попросил продумать заранее.
- Отклонено: список ссылок по протоколу git (`info/refs`) — доказывает лишь, что репозиторий клонируется анонимно, то
  есть то самое правило «на репозиторий»; скачивание и разбор pack-файла в Worker'е — слишком тяжело; запрос на каждый
  коммит — не влезает в бюджет; доверять хосту из заявки — см. следующий раздел.

## Что резервируется уже сейчас (C3, внутри I1)

Четыре заготовки без поведения попадают в формат передачи v1 до его заморозки — иначе позже понадобился бы `/ingest/v2`.

| Что | Где | Поведение до I5 / I6 |
|---|---|---|
| Шов (заготовленное место в коде) `resolveLocalVisibility()` | `src/ingest/visibility.ts` | Всегда отвечает «приватно» |
| Необязательное поле `WireRepo.claim` — заявка | `src/ingest/wire.ts`, `guard.ts` | Валидатор его знает; Worker принимает и не читает |
| Поле `publicHosts` в ответе проверочного запроса | `src/ingest/handler.ts` | Пустой массив |
| Имя переменной `PUBLIC_HOSTS` | `src/config.ts` (I6) | Не задана → 0 запросов, поведение форков не меняется |

- Заявка отправляется **только для репозиториев в режиме `text`**; `counters` означает «только цифры, всегда».
- Для GitHub в заявке хеш `gh:<12 hex sha256(owner/name строчными)>` — имя по сети не идёт.
- Для других хостингов в заявке путь `хост/пространство/репозиторий`. Он идёт на свой Worker, в отчёт не попадает, и
  только если Worker сам назвал этот хост в `publicHosts`. Это единственное исключение из списка «не уходит никогда»
  ([02-privacy.md](02-privacy.md)).
- Слияние (`mergeLocal`) с I1 умеет делить один репозиторий на публичную часть и приватный остаток; путь выключен.
- Коммит, уже учтённый как приватный, позже именем не «доотображается»: вышедшие отчёты не переписываются.

## Что может утёкший токен

Без защит публичная видимость расширила бы возможности атакующего: сегодня при `redact` утёкший `INGEST_TOKEN` даёт
только фальшивые цифры, а с наивной проверкой дал бы чужой текст под именем владельца.

| | Наивная публичная видимость | С защитами этого документа |
|---|---|---|
| Свой текст и имя в отчёт, включая публичный | да — через форк с подделанным автором | **нет**: текст только из ответа хостинга, коммит обязан быть в ветке по умолчанию репозитория из списка Worker'а |
| Вредные указания для модели и текст в Telegram | да | нет |
| Увести Worker на произвольный адрес | да — хост из заявки | **нет**: только `PUBLIC_HOSTS`, без перенаправлений |
| Выжечь 50 внешних запросов, чтобы прогон упал на вызове модели или записи отчёта | да | **нет**: +1 запрос (GitHub) и не больше 6 (другие хостинги) |
| Показать настоящие публичные коммиты владельца под настоящим именем | да | да — это они и есть |
| Узнать `text.allowed`, `why` и `publicHosts` | да | да — сведения и так публичные |

Общий радиус поражения токена — в [08-threat-model.md](08-threat-model.md); лечение прежнее: ротация, затем откат и
перезапуск, если прогон уже прошёл.

## Сбои и бюджет

Любой сбой оставляет заявленное приватным в этом прогоне; повторов нет, кэша результатов в KV нет.

- Сбоем считается: сеть, 5xx, 3xx, 4xx, ответ не в формате JSON, превышение бюджета, частичная ошибка GraphQL по одному
  репозиторию, таймаут. Итог — счётчик `publicUnverified` в сноске, ноль вызовов модели, отчёт выходит.
- Почему без повторов и кэша: повтор тратит внешние запросы основной работы; кэш — лишняя подвижная часть, а при откате
  прогона всё равно пересчитывается.
- Бюджет внешних запросов на Free (50 на вызов, **подтверждено** панелью и документацией): сегодня 15–26; I1 добавляет
  1 (приватность репозитория отчётов), I5 — 1, I6 — не больше 6. Итого не больше 34 при наблюдаемых значениях.
- Честно: теоретический максимум нынешнего прогона уже выше 50 (около 56, [04-findings.md](04-findings.md)). Новые
  запросы безопасны при наблюдаемых 15–26, но не в худшем случае; поэтому бюджет проверки публичности мал и фиксирован.

## Приёмка

Обе части принимаются тестами на подделку, а не на «счастливый путь».

| Часть | Приёмка |
|---|---|
| **C5** (внутри I5): `src/ingest/verify-github.ts` | Ответ с `aheadBy > 0` и «правильным» логином → приватно. Репозиторий не из списка Worker'а → приватно. Частичная ошибка → приватен только этот репозиторий. Сбой запроса → отчёт выходит, всё заявленное приватно. Ровно +1 внешний запрос. При `redact` публичные коммиты показаны с именем, остаток — `private-project-N` |
| **C6** (I6): `src/ingest/verify-forge.ts`, разбор `PUBLIC_HOSTS` | Ни один такой запрос не несёт `Authorization` или `Cookie`. Хост вне `PUBLIC_HOSTS` не запрашивается. 3xx, 404 и не-JSON → приватно. Седьмой запрос не делается. Без переменной — 0 запросов и пустой `publicHosts`. Замер с настоящего Worker'а: отвечает ли хостинг адресам Cloudflare |
