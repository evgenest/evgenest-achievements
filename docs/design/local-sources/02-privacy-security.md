# 02. Приватность и безопасность

Инструмент читает домашнюю папку разработчика и (по желанию) транскрипты чатов, а отчёт может
уходить в публичный репозиторий. Поэтому всё по умолчанию закрыто, а каждое расширение — явный
выбор пользователя.

## Что покидает машину

| Режим | Что уходит | Куда попадает |
|---|---|---|
| **`share: "counters"`** (по умолчанию) | `id` репо (хеш корневого коммита + пути remote), SHA, даты автора/коммиттера (UTC, до секунды), additions/deletions, счётчики диагностики, случайный `machineId`, версия collector'а | KV ≤ 45 дней; в отчёт — только суммы; в LLM — счётчики и «минут между коммитами» (как сейчас для GitHub) |
| **`share: "text"`** (opt-in, глобально или на хост) | + имя репо, заголовок и тело коммита — после скраббинга секретов и обрезки | KV ≤ 45 дней; отчёт, LLM-провайдер и **Telegram** — только при `PRIVATE_REPOS=full` и подтверждённо приватном reports-репо |
| **`sessions: "time"`** (opt-in, I3) | + метки времени человеческих промптов, округлённые до минуты | KV ≤ 45 дней; в отчёт и LLM — три числа |
| **`sessions: "projects"`** | + ключ проекта на сессию: `id` репо или `gh:<хеш owner/name>` (имя GitHub-репозитория в открытом виде не уходит; Worker сопоставляет хеш со своим списком репозиториев) | то же + время по проектам |
| **`sessions: "titles"`** | + заголовок сессии (`aiTitle`) — это **пересказ промпта моделью**, может содержать имена клиентов и детали инцидентов. Только для сессий в репозиториях с `share: "text"` (для GitHub-репозиториев — по общему правилу подтверждения) | как `text`: только при `full` + приватный reports-репо; иначе отбрасывается |

Никогда, ни в одном режиме: абсолютные пути, `cwd`, slug из `~/.claude/projects`, hostname, имя
пользователя ОС, e-mail'ы, имена веток, URL/хосты remote'ов, имена файлов, диффы, текст промптов
и ответов, `lastPrompt`, вывод инструментов.

Оговорки:

- **Псевдонимы, не анонимность.** SHA и корневой коммит публичного проекта находятся поиском.
  Секундные метки + размеры коммитов — отпечаток активности. Поэтому область сбора (ниже) важнее
  режима `share`.
- **Интерактивный вывод** `scan`, `init`, `doctor` показывает локальные пути и хосты — иначе ими
  нельзя пользоваться. Вывод `push`, `--verbose` и всё, что пишет запуск по расписанию, — никогда.
  Canary-тест покрывает `push`, `--dry-run` и `--verbose`.
- URL remote'а разбирается только в памяти; `user:token@` отрезается первым делом.
- `push --dry-run` печатает **ровно те байты**, которые уйдут (тот же путь кода, с инъекцией часов).
- При превышении размера снимок деградирует предсказуемо: сначала отбрасываются `message` (старые
  первыми), затем `headline`, затем ошибка. Коммиты и даты не отбрасываются никогда; счётчик `textDropped`.

## Текст уходит только после подтверждения

1. `push` начинает с probe-запроса. Текст коммитов **и заголовки сессий** включаются, только если
   ответ **этого** probe подтвердил `privacy === "full" && reportsPrivate === true`. Иначе
   collector молча понижает до `counters` и пишет счётчик `textDowngraded` — предупреждения в
   journald никто не читает.
2. `reportsPrivate` — результат проверки `REPORTS_REPO` (`visibility === "private"`), которую
   Worker делает в каждом прогоне **с заданным `INGEST_TOKEN`** и в роутах владельца. Чтобы первый
   же отчёт был с текстом: `GET /ingest/preview` (обновит политику) → `push`.
3. Worker со своей стороны отбрасывает текст локальных репо и заголовки, если приватность не
   подтверждена **в этом прогоне** (fail-closed, тот же приём, что в `repo-visibility.ts`). Сбой
   lookup'а отбрасывает текст этого прогона, но сохранённую политику не портит.
4. Держатель утёкшего токена probe не обязан соблюдать — но gate на Worker'е (п. 3) действует и на него.

Чего Worker **не** проверяет: приватность Telegram-чата. Если `TELEGRAM_CHAT_ID` — группа или
канал, имена и факты из `full`-режима увидят все её участники (это верно и сегодня для приватных
GitHub-репозиториев). Текст уже лежащий в KV и уже закоммиченные отчёты не отзываются, если
reports-репозиторий позже сделать публичным.

Рецепт владельца для осмысленных сводок по forge-репозиториям:
`"hosts": { "<forge-host>": { "share": "text" } }` + `PRIVATE_REPOS=full` + приватный
reports-репо + LLM-провайдер с ZDR + личный Telegram-чат. Получатели имён и фактов в этом режиме:
reports-репо, LLM-провайдер, Telegram.

## Область сбора

`roots` по умолчанию — домашняя папка, поэтому критично, **что** из найденного отправляется:

| Класс репозитория | По умолчанию |
|---|---|
| GitHub-remote, владелец из `githubOwners` | Пропуск — его собирает Worker |
| GitHub-remote чужого владельца (`github-foreign`, I2) | Пропуск; показан в `scan`; включается явным `include` |
| Все remote'ы попадают в белый список `hosts` | Собирается |
| Есть remote вне белого списка | Пропуск; `push` печатает «N пропущено: необъявленный хост» |
| Нет remote'ов | Собирается, только если `includeNoRemote: true` (вопрос в `init`) |
| Partial clone / promisor remote | Пропуск всегда (см. модель угроз) |

До I2 (пока нет `githubOwners`) пропускаются все репозитории с любым GitHub-remote.

- Запись белого списка — `host` **или `host/префикс-пространства-имён`**: на общих SaaS-forge
  объявить хост ради личных репо значило бы впустить и пространство имён работодателя. Префикс
  сравнивается в памяти и не сериализуется. `init` группирует найденное по «хост + первый сегмент
  пути» и **ничего не отмечает заранее**.
- Хост определяется через `git remote get-url --all` (с учётом `insteadOf`-алиасов), а не по
  сырому значению из конфига — иначе GitHub-репо под алиасом `gh:` обойдёт правило пропуска.
- Локальные `user.email` автоматически добавляются в набор «своих» только из репозиториев,
  которые сами прошли отбор; остальные `init` показывает для явного подтверждения.
- **Сессии подчиняются той же области.** Collector читает `cwd` записи **в памяти**.
  `sessionsScope: "collected"` (по умолчанию) = собираемые локальные репозитории +
  GitHub-репозитории из `githubOwners`, не из `exclude`; `cwd` вне любого репозитория
  отбрасывается. Остальное — в счётчик `promptsSkippedScope`. При `"all"` уходит всё, вне
  репозитория — с `repo: null`.
- ssh-алиасы из `~/.ssh/config` git не раскрывает: такой хост объявляется в `hosts` как есть.

## Видимость и политика

- Любой локальный репозиторий — `isPrivate: true`. У Worker'а нет способа проверить видимость,
  а GitHub-remote не признак публичности. Видимость «public» на хост — открытый вопрос (README, п. 7).
- Политика публикации — единственная ручка `PRIVATE_REPOS`, как для приватных GitHub-репо.
  Поведение локальных чисел в каждом режиме — таблица в [01](01-architecture.md#слияние).
- I0 переводит `redactPrivate` на явные списки полей. Сегодня это не утечка (все потребители
  читают именованные поля), а мина: spread оставляет на объекте любое новое поле, а
  `{...state.lastWeek}` в `sanitize.ts` уже сейчас роняет прогон при любом расширении state.
  Режим `full` по замыслу не проецируется.

## Секреты и радиус поражения

| Секрет | Где живёт | Что может | Чего не может |
|---|---|---|---|
| `INGEST_TOKEN` (новый, необязательный) | Worker + файл `credentials` (0600) в каталоге состояния или env на каждой машине | Перезаписать снимок машины: фейковая локальная статистика, формулировки отчёта; **вытеснить реальные данные лимитами**; на Free — исчерпать суточные KV-квоты аккаунта и этим заблокировать или задвоить недельный прогон; **занять свободные слоты индекса машин**; при `full` + приватном reports-репо — прислать текст напрямую (в отчёт, LLM, Telegram); прочитать три факта конфигурации (`privacy`, `reportsPrivate`, `supported`) и косвенно — заполненность индекса (409) | Читать данные, запускать прогоны (траты на LLM), удалять state |
| `RUN_SECRET` (как сейчас) | Worker + владелец | `/run`, `/state`; новое: список машин и метаданные push'ей, preview (счётчики), удаление снимков машин | Писать в `PUT /ingest` — отклоняется явно |

Лекарство от утёкшего токена — ротация **плюс аудит** ([05](05-operations.md)). Ротация сама
обесценивает всё, присланное старым токеном: снимок помечен отпечатком токена (`tk`), и прогон
отбрасывает и снимает чужие. Настоящие машины данные не теряют (окно 35 дней). Если прогон уже
прошёл с подложенными данными — откат `DELETE /state/latest` и перезапуск.

Токен и `machineId` лежат **не** рядом с `config.json`, а в каталоге состояния
(`${XDG_STATE_HOME:-~/.local/state}/achievements-collector/`, Windows — `%LOCALAPPDATA%`):
`~/.config` часто синхронизируется через dotfiles, и общий `machineId` заставил бы машины каждый
час затирать снимки друг друга. `doctor` предупреждает, если конфиг лежит внутри git-дерева.
Endpoint — только `https://` (кроме localhost).

## Данные в покое

| Где | Что | Сколько |
|---|---|---|
| KV `ingest:v1:<machineId>` | Снимок: SHA, даты, размеры; при `text` — имена и сообщения коммитов приватных репо (после скраббинга); при сессиях — минутные метки промптов, ключи проектов, заголовки | TTL 45 дней, ≤ 2 MiB, ≤ 5 машин |
| KV `ingest:v1:index`, `ingest:v1:policy` | Список `machineId`; имя reports-репо и результат проверки его приватности | Индекс самоочищается: прогон снимает записи без снимка. Байты |
| Снимки state (52 шт.) | Ledger: усечённые хеши ключей + 10 hex SHA — локальных **и GitHub**-коммитов; с I3 — учтённые интервалы сессий | ~год; ~30 байт на коммит |
| Каталог состояния collector'а (0700; файлы 0600) | `credentials`, `machine-id`, `last-push.json`; с I3 `prompt-cache.json` — минутные метки промптов и ключи проектов, **переживают удаление транскрипта** | метки — окно снимка (35 дней; до 120 при backfill); заголовки не кэшируются |

Очистка: `DELETE /ingest/v1/<machineId>` или команды `wrangler kv` из [05](05-operations.md).

## Модель угроз (новая поверхность)

| Угроза | Защита |
|---|---|
| Утёк `INGEST_TOKEN` | Только запись; индекс машин вместо `list` на пути атакующего; лимит размера; лимит на прогон делится поровну между машинами — фейковая машина не вытеснит реальные целиком; прогон читает только машины из индекса. Остаточный риск на Free — исчерпание квот KV → ротация |
| Вредоносный / огромный снимок | Размер проверяется до чтения; снимки обрабатываются по одному, сначала `metadata.bytes`; битый снимок пропускает машину, не неделю; имя репо, похожее на секрет, не роняет LLM-guard, а заменяется на `local/<id>` |
| Подделка записей `git log` враждебным репозиторием | Разделители — только NUL (`-z`, `%x00`): git не допускает NUL в сообщении, а `%ae`/`%b` обрезаются на нём. Любой другой байт (`\x1e`, `\x1f`, `\x1d`) подделывается телом коммита или e-mail'ом автора — проверено фикстурой. Плюс строгий разбор: число полей, hex SHA, ровно одна строка shortstat на запись, e-mail — точное равенство без управляющих символов |
| Исполнение чужого кода при сканировании | `GIT_NO_LAZY_FETCH=1` (git ≥ 2.45) **и** пропуск репозиториев с `extensions.partialClone` / `remote.*.promisor` на любой версии: lazy fetch во враждебном partial-clone исполняет код при обычном `git log` (через `ext::`, `core.sshCommand`, `uploadpack` — проверено фикстурами). Плюс: типизированный набор команд, argv без shell, `--no-ext-diff --no-textconv`, `core.fsmonitor=false`, окружение с нуля, таймаут. `safe.directory=*` в глобальном конфиге пользователя эту защиту git снимает — `doctor` предупреждает |
| Prompt-injection через локальный текст | Поза не меняется: текст коммитов с GitHub уже недоверенный вход; модель отчёта без инструментов |
| Секрет в сообщении коммита | Скраббинг на клиенте (общий `src/secrets.ts`) и на Worker'е; заголовки — ещё и перед `report.ts`. Скраббер — эвристика для учётных данных, не фильтр приватности |
| Подмена markdown/HTML в заголовке или имени | Нейтрализация перед вставкой в отчёт |
| Supply chain | Collector — в том же репо, что и Worker; ноль runtime-зависимостей, `bun install` для него не нужен; сеть — один файл `transport.ts` (grep-тест); никаких `curl \| sh`. npm — только с trusted publishing и provenance |
| Утечка пути/хоста/e-mail через новое поле | Закрытая wire-схема (включая ключи диагностики и формат версии); canary-тест снимка и вывода `push`; сериализованная неделя при `redact`/`skip` не содержит имени локального репо, значения SHA, `machineId` — включая сноску и LLM-payload |
| 403/503 от защиты зоны Cloudflare принят за «плохой токен» | Заголовок `X-Ingest: 1` на ответах Worker'а (кроме 404 выключенной фичи); рекомендуем `workers.dev` |
| Формат сессий Claude Code сломался | Терпимый читатель: сбой → меньше/ноль промптов + счётчик, никогда не падение push |
| Удалённая сессия продолжает публиковаться из кэша | Кэшируются только метки времени и ключ проекта; **заголовок отправляется, только пока существует транскрипт**. `collector sessions forget [--all]` чистит кэш; следующий push перезапишет снимок в KV |
