# 05. Эксплуатация

Как фичей пользоваться после первой установки. Все имена и адреса — заполнители.

## Обновление

Порядок: **сначала Worker, потом машины.**

1. Задеплоить Worker.
2. На каждой машине: обновить выделенный клон collector'а до нужного закреплённого коммита
   (позже — тега релиза).

`push` читает `supported` из последнего ответа и завершается с понятной ошибкой, если его схемы
там нет. 404 от `/ingest/v2` → откат на `v1`; 404 от `v1` → фича выключена. Worker терпим к
неизвестным полям (считает их в сноску), поэтому collector чуть новее Worker'а данные не теряет.

## Токен: создание и ротация

Значение секрета из Cloudflare прочитать нельзя — поэтому сначала сохранить, потом отправить:

```
T=$(openssl rand -hex 32)
printf %s "$T" | wrangler secret put INGEST_TOKEN -c wrangler.prod.jsonc
D="${XDG_STATE_HOME:-$HOME/.local/state}/achievements-collector"
( umask 077; mkdir -p "$D"; printf %s "$T" > "$D/credentials" )
unset T
```

Без `-c wrangler.prod.jsonc` секрет уйдёт Worker'у с именем из шаблона. На остальные машины токен
переносится вручную. `INGEST_TOKEN` не должен совпадать с `RUN_SECRET` — Worker это проверяет и
выключает ingest.

Ротация (в том числе после утечки):

1. Та же команда — новый токен; обновить `credentials` на каждой машине. Пока машина шлёт старый
   токен, она получает 403; **данные не теряются** — следующий успешный push принесёт всё окно.
2. Снимки, присланные старым токеном, прогон отбросит и снимет сам (отпечаток токена в
   метаданных). Проверить: `GET /ingest` — незнакомые `machineId` удалить роутом `DELETE`.
3. Если прогон **уже прошёл** с подложенными данными — `DELETE /state/latest` и перезапуск.
4. Экстренно выключить фичу: `wrangler secret delete INGEST_TOKEN -c wrangler.prod.jsonc` —
   `/ingest*` станет 404; чистить тогда командами `wrangler kv … --remote` ниже.

## Машины

- **Добавить вторую:** клон, конфиг, `credentials`, push. `machine-id` создаётся сам. В первый
  отчёт придёт до 28 дней ни разу не учтённой работы с этой машины как «опоздавшая»; не нужно —
  `"notBefore": "<дата>"`.
- **Убрать:** `curl -X DELETE -H "Authorization: Bearer <RUN_SECRET>" https://<worker-url>/ingest/v1/<machineId>`.
  Иначе ключ держит один из пяти слотов, пока не истечёт TTL снимка (45 дней) и ближайший
  прогон не снимет запись из индекса.
- **Посмотреть:** `curl -H "Authorization: Bearer <RUN_SECRET>" https://<worker-url>/ingest`.
- Вручную через wrangler (обязательно `--remote`, иначе команда работает с локальным хранилищем и
  «успешно» ничего не делает):

```
wrangler kv key list   --binding STATE --prefix ingest:v1: --remote -c wrangler.prod.jsonc
wrangler kv key delete 'ingest:v1:<machineId>' --binding STATE --remote -c wrangler.prod.jsonc
```

  После ручного удаления ключа запись в индексе снимет ближайший прогон; роут `DELETE` делает
  оба действия сразу.
- Машина, получившая 409 (слоты заняты), завершает `push` с ненулевым кодом и строкой в stderr
  даже при `--quiet` — смотрите журнал расписания.
- Не синхронизируйте каталог состояния collector'а между машинами: общий `machine-id` заставит их
  затирать снимки друг друга.

## «Где мои коммиты?»

1. `bun run collector scan --explain <путь>` — класс репозитория и причины: чужой e-mail, вне
   окна, merge, необъявленный хост, GitHub-remote, partial clone.
2. `bun run collector push --dry-run` — есть ли коммит в снимке.
3. `GET /ingest/preview` (под `RUN_SECRET`) — что Worker выбрал бы прямо сейчас: по машинам —
   валиден ли снимок, выбрано, опоздавших, отложено, сгорело, отброшено как дубль / как GitHub.
   Без LLM, без коммита отчёта, без записи state.
4. Сноска в отчёте: опоздавшие, отложенные, сгоревшие; машины, молчащие > 48 ч; отклонённые снимки.

## Backfill: вернуть уже потерянные недели

Первый прогон с фичей считает только текущую неделю. Вернуть прошлые можно, но это **переписывает
старые отчёты, заново шлёт Telegram и стоит LLM-вызовов**.

0. Остановить расписание collector'а на время backfill.
1. `bun run collector push --window-days <минимально нужное N>` (≤ 120). В `--dry-run` проверить
   `textDropped`: при большом окне с текстом снимок упирается в 2 MiB, и первыми отбрасываются
   сообщения самых старых — то есть как раз возвращаемых — недель.
2. `DELETE /state/latest`, пока `GET /state` не покажет, что `until` текущего снимка ≤ начала
   самой старой возвращаемой недели. Снимков может быть больше, чем недель (ручные и тестовые
   прогоны); все недели после неё тоже пересобираются.
3. `/run?date=YYYY-MM-DD` по одной дате, **от старой к новой**, каждый раз дожидаясь нового
   снимка с нужным `until` в `GET /state` (`/run` только ставит задачу в очередь).
4. `bun run collector push --window-days 0`, включить расписание.

Оговорки:

- Нужен `history(until:)` из I0 — иначе GitHub-часть старой недели захватит более поздние коммиты.
- Поиск PR/issues, CI и deployments сверху **не ограничен**: более поздние PR и issues попадут в
  каждую пересобранную неделю и задвоят `allTime.prs` / `allTime.issues`.
- GitHub-часть старых недель пересобирается неточно: список репозиториев берётся по нынешней
  свежести push (первые `MAX_REPOS`), до 100 коммитов на репо. `MAX_LOOKBACK` ограничивает длину
  одного прогона, а не глубину `?date=`; глубину ограничивают окно снимка и число снимков state.
- Путь отчёта выводится из `until` в UTC: при `TIMEZONE` ≥ UTC+10 дата в пути сдвигается, и
  старый файл не перезаписывается, а появляется второй.

## Локальная разработка

С шаблонным `wrangler.jsonc` `INGEST_TOKEN` из `.dev.vars` **молча игнорируется**: при наличии
блока `secrets.required` `wrangler dev` грузит только перечисленные в нём ключи. Запускать так:

```
wrangler dev --var INGEST_TOKEN:<dev-token>        # или: bun run dev:ingest
```

С `wrangler.prod.jsonc` (в нём блока `secrets` нет) `.dev.vars` грузится целиком — поведение двух
конфигов различается.

Проверка приёмки I1: `DELETE /state/latest` (снять настоящую неделю) → `GET /ingest/preview`
(обновит политику приватности — без этого первый снимок уйдёт без текста) → `push --dry-run`
(текст на месте?) → `push` → `/run?date=<пятница>`. Без отката `?date=` уже отчитанной недели даёт
`since ≥ until`, и локально ничего не выберется.

## Workers Free

Лимит 10 мс CPU на Free действует и на cron, и на consumer очереди. До решения по вопросу 1
([README](README.md#открытые-вопросы-к-владельцу)) локальные источники на Free не обещаем.
Суточные квоты KV на Free считаются **на аккаунт** — исчерпание затрагивает и другие Worker'ы.
