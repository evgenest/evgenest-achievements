## Главное за минуту

Три анонсированных направления спроектированы вместе и стоят на одной общей основе — записи недели; сначала идут две
срочные мелочи, затем запись недели, и только потом всё остальное.

- **Что строим.** Локальные источники: работа вне GitHub и сессии Claude Code попадают в тот же недельный отчёт.
  Тренды: короткий блок «На дистанции» в недельном отчёте. Ретроспективы: отдельный файл за месяц и за год.
- **Общая основа — запись недели.** Сырьё не хранится, поэтому каждый прогон один раз кладёт около 2 КБ чисел о неделе
  в конец файла отчёта и в state. Тренды и ретроспективы читают только её и готовые отчёты.
- **Срочно два шага.** S0: сегодня лог ошибки модели содержит её ответ целиком (`src/llm.ts:214`), а сохранённые трассы
  Cloudflare — полные адреса запросов (`wrangler.jsonc:22-26`). R0: каждая пятница без записи недели навсегда теряет
  минуты по проектам и счётчики событий PR и issues.
- **Пока локальные источники (I1) не вышли,** владелец сам выпускает каждую пятницу корректирующий отчёт о локальной
  работе (три шага, инструкция в 05-operations); после I1 — один общий отчёт на неделю.
- **Жёсткая дата одна:** годовая ретроспектива за 2026 год должна прийти в пятницу 1 января 2027 (R4).
- **Цена.** Запись недели и тренды: +0 внешних запросов, +0 вызовов модели. Локальные источники: +1 запрос за прогон.
  Ретроспективы: отдельный запуск, 13 вызовов модели в год и только при `RETROSPECTIVES=true`.
- **Workers Free.** Проверено на Free: недельный прогон 40–110 мс процессора проходит; Cloudflare этого не гарантирует;
  для больших объёмов надёжнее платный тариф.
- **От владельца нужны** ответы на девять вопросов; №3, №5 и №9 — до первых же итераций.

## Сквозные принципы

Девять правил, общих для всех папок; папки на них ссылаются и от итерации к итерации их не пересматривают.

- **P1. Долгая память проекта — готовые отчёты.** Сырьё не хранится: после попадания в отчёт текст коммитов нигде, кроме
  отчёта, не остаётся. KV — транзитный буфер; источник истины для текста — git на машине.
- **P2. Всё нужное записывается сразу.** Что когда-нибудь понадобится трендам и ретроспективам, попадает в запись недели
  в момент сборки отчёта: задним числом это не восстановить.
- **P3. Запись недели живёт там, куда и так пишем:** невидимым комментарием в конце файла отчёта (вечный архив) и в поле
  `history` снимка state (последние 53 недели; откатывается вместе с ним). Новых хранилищ и ключей KV нет.
- **P4. В репозиторий отчётов попадает только то, что прошло политику приватности:** у чужого форка он может быть публичным.
- **P5. Сбой новой части ухудшает отчёт** (нет раздела, сноска), **но не роняет его.** Ретроспективы идут отдельным
  запуском и физически не могут уронить недельный отчёт.
- **P6. Проект публичный.** Без новых переменных у чужих форков не появляются платные вызовы модели и сообщения. Видимые
  изменения ведутся одним списком «Изменения поведения», каждое подтверждает владелец.
- **P7. Workers Free поддерживается формулировкой «проверено, не гарантировано»;** нарезки прогона на куски по 10 мс нет.
  Процессорное время меряется в локальном движке Cloudflare (workerd через `wrangler dev`): Node и Bun занижают, в
  workerd цифры в 1,5–3 раза выше.
- **P8. Настройка простая:** одно решение на репозиторий — с текстом, только цифры, не собирать. Постороннему по умолчанию
  только цифры; владельцу своего сервера — одна строка «весь сервер с текстом».
- **P9. Публичным считается только то, что Worker сам прочитал у хостинга;** имя и текст для публичного показа берутся
  из ответа хостинга, никогда с машины.

## Словарь

Каждый термин объяснён одной строкой; встретив в папках непонятное слово, ищите его здесь.

| Термин | Что значит |
|---|---|
| Worker · прогон | Программа на Cloudflare, которая раз в неделю (cron, пятница 08:00 UTC) собирает отчёт; один запуск — прогон; ручной — `POST /run` |
| Форк | Чужая копия этого публичного проекта со своим Worker'ом и своим репозиторием отчётов, возможно публичным |
| Репозиторий отчётов | Отдельный репозиторий на GitHub, куда Worker пишет файлы отчётов; у владельца он приватный |
| KV · state · снимок state | KV — хранилище Cloudflare «ключ → значение». State — счётчики проекта в нём; каждый прогон дописывает снимок `state:<время>`, хранятся 52 последних |
| Откат · перезапуск | `DELETE /state/latest` снимает верхний снимок state, то есть последний прогон; `/run?date=…` собирает ту же неделю заново |
| Откат деплоя | Возврат Worker'а на более старый код. На код не старше I0-минимума он ничего не стирает: незнакомые поля state переносятся как есть (целыми, но без недель старого кода). Код старше I0-минимума стирает `history`, `career` и журнал учтённого: первые два восстанавливает `records-rebuild`, журнал начинается заново |
| Догоняющий прогон | Прогон после пропущенных пятниц: один отчёт за период до 28 дней |
| Запись недели | Около 2 КБ машинных чисел о неделе, собранных в момент сборки отчёта; лежит невидимым комментарием в конце файла отчёта и в `history` |
| `history` · `career` | Поля state: рабочая копия записей последних 53 недель · накопитель «с начала наблюдений» |
| Запись периода · отпечаток входов | То же для месяца и года, в конце файла ретроспективы · лежащий в ней список недель, из которых файл собран: совпал с `history` — повтор ничего не тратит |
| Бэкфилл (backfill) | Разовое восстановление записей недель, вышедших до R0 (сегодня их 8), из старых отчётов локальным скриптом (R1) |
| Файл-сирота | Отчёт отменённого прогона, на который state больше не указывает |
| Основной · корректирующий · общий отчёт | Нынешний недельный отчёт (только GitHub) · файл `<день>_local.md` рядом с ним о локальной работе недели, вышедшей до I1; state не меняет · отчёт после I1: всё в одном файле |
| Collector · снимок машины | Маленькая программа на машине разработчика; раз в час шлёт Worker'у снимок — один JSON с событиями машины, один ключ KV, каждая отправка заменяет его целиком |
| Транзитный буфер | Роль KV для текста коммитов: текст лежит там проездом, пока коммит не попал в отчёт (и ещё один прогон при грейсе); снимок живёт не дольше 9 дней |
| Журнал учтённого (ledger) | Короткие хеши уже посчитанных коммитов внутри state; отвечает за «не учесть дважды», откатывается вместе со state |
| Список учтённого | Копия журнала в ключе KV, которую читает collector, чтобы не присылать уже учтённое; подсказка, а не источник истины |
| Проверочный запрос | `GET`, которым collector перед каждой отправкой спрашивает Worker: можно ли слать текст и что уже учтено |
| Грейс | Отсрочка в один прогон: машинам публикуется журнал state, бывшего до последнего прогона, поэтому текст последней отчитанной недели ещё лежит в снимках и откат + немедленный перезапуск работает без ожидания отправки |
| Родословная снимка (полнота) | Проверка «снимок машины собран не по устаревшему списку». Collector не присылает уже учтённое; после отката Worker «забывает» последнюю неделю, а снимок, собранный до отката, её коммитов не содержит — он неполон. Worker узнаёт это по метке `through`, которую collector возвращает вместе со снимком. Неполный снимок: ручной `/run` → 409, cron — считает что есть и пишет сноску |
| `K` · `hk` · замыкание ключей | У коммита два опознавательных ключа: SHA и `K` — «секунда автора + сколько строк добавлено и удалено» (переживает rebase, при котором SHA меняется). `hk` — хеш от `K` с подмешанным id репозитория, чтобы по опубликованному хешу нельзя было перебором восстановить время коммита. Замыкание ключей: копия, опознанная как учтённая по одному ключу, получает в журнале и второй — в следующий раз совпадут оба, и она перестанет отправляться |
| Опоздавшие · отложено · сгорело | Коммит, написанный до начала недели, но приехавший позже · не влез в лимит прогона и ждёт следующего · лежал в снимках, но за 28 дней так и не был выбран: в отчёт не попал, виден только счётчиком в сноске. Работа машины, молчавшей дольше ~28 суток, сюда не входит: Worker её не видел, она не посчитана вовсе |
| I1-T · I1-P | Две части итерации I1: передача «только неучтённое» · её обязательная проверка моделью с эталоном |
| Формат передачи (wire) | Схема JSON-снимка, версия 1; замораживается в конце I1, дальше любое изменение формы — это `/ingest/v2` |
| `text` · `counters` · `off` | Решение о репозитории на машине: с описанием · только цифры · не собирать |
| `full` · `redact` · `skip` | Режим `PRIVATE_REPOS` на Worker'е: приватное по именам · без имён (`private-project-N`) · не учитывать вовсе |
| При сомнении — скрыть | Любой сбой проверки считается отказом: лучше блёклая строка, чем утёкший текст (англ. fail-closed) |
| Данные для модели · их защита | JSON, уходящий модели · список разрешённых ключей, который бросает исключение на любом незнакомом |
| Запасной путь | Второй способ сделать то же при сбое первого: текстовый вызов модели вместо строгой схемы, запасная формула часов |
| Чистая функция | Функция, результат которой зависит только от аргументов: не ходит в сеть и KV, не смотрит на часы — поэтому проверяется простым тестом |
| Золотой файл | Эталонный файл в тестах, с которым результат сверяется байт в байт |
| Метка-приманка (canary) | Приметная строка, подложенная в тестовые данные: её не должно оказаться там, куда приватное попадать не должно |
| Проверка на случайных сценариях | Тест на сотнях выдуманных историй (генератор с фиксированным зерном): проверяет свойство, а не пример, — скажем, «сумма недель = месяц» (англ. property tests) |
| Модель с эталоном (I1-P) | Две системы идут по одной случайной истории — прежняя «полное окно» и новая «только неучтённое»; результаты обязаны совпасть |
| Проверка на прочность | Придирчивая проверка дизайна до кода независимыми проверяющими: намеренный поиск утечек, подделок и гонок (англ. adversarial review) |
| Сравнимая неделя · «обычное» · коридор | Неделя длиной 5–9,5 дня · до 12 последних сравнимых недель того же режима · средняя половина этого ряда |
| Разрыв ряда | Смена набора источников или метода расчёта часов: сравнение копится заново, в блоке одна сноска |
| Массовый коммит · загруженные документы | GitHub-коммит от 10 000 строк · строки PDF, писем, офисных и lock-файлов в локальных коммитах; ни то ни другое — не объём работы |
| Часы в фокусе · время в паре с ИИ | Оценка чистых часов по коммитам на одной общей шкале времени · отдельная метрика по промптам сессий; с часами не складывается никогда |
| Внешний запрос · workerd | Исходящий запрос Worker'а наружу, на Free их 50 на запуск (англ. subrequest) · локальный движок Cloudflare, в нём меряется процессорное время |
| Очередь · подтверждение (ack) | Очередь Cloudflare, через которую идут ручные прогоны и ретроспективы · подтвердить сообщение — значит «больше не доставлять» |
| Трассы · радиус поражения | Сохранённые Cloudflare записи о каждом запросе Worker'а, включая полные адреса исходящих запросов · что может сделать тот, кому достался секрет |
| Шов · каталог состояния | Заготовленное место в коде без поведения · папка collector'а вне `~/.config` для токена и номера машины |
| Словарь замен · подметание | Необязательная A1: замена личных имён на роли до модели · повторный проход словарём по готовому тексту |
| Принятое допущение | Мелкое решение, принятое авторами дизайна без владельца, потому что решения от 2026-09-19 об этом молчали; помечено в тексте, дёшево изменить |

   владельца и расходится с принятой глубиной «проекты и заголовки» —
   [таблица в 03b-sessions](local-sources/03b-sessions.md#один-переключатель-что-уходит-о-сессии). Возразить — до I3.
2. Длина коротких хешей журнала учтённого — 10 и 12 hex-символов; менять формат позже дорого. Возразить — до первого
   боевого прогона I1.
3. В записи нет поля «сколько строк вычтено как загруженные документы»; у трёх корректирующих файлов это число остаётся
   только в видимой сноске. Лечится необязательным полем, версия схемы не меняется. Возразить — до R0.
4. Строка «с начала наблюдений» навсегда занижена на локальную работу недель до I1. Возразить нельзя: это следствие
   решения «корректирующие отчёты state не меняют»; только к сведению.
5. Бэкфилл убирает из проектов старых недель строку самого репозитория отчётов (итоги не трогает) — иначе ложная серия.
   Возразить — до R1.
6. Ручки «не раньше даты» больше нет: новая машина привезёт до 28 дней работы опоздавшей; лишнее — в `off` до первой
   отправки. Возразить — до I1.
7. `INGEST_TOKEN` один на все машины; второго числа «работа агента без присмотра» в метрике сессий нет. Возразить можно
   в любой момент: формат передачи от этого не меняется.

**Известные пределы (только к сведению, делать ничего не нужно):**

- Работа машины, молчавшей дольше ~28 суток, после пробуждения в отчёт не попадает и счётчиком не видна; нового механизма
  не вводим ([сценарий S14](local-sources/07-selection.md#сценарии)). Корректирующие отчёты после выхода I1 не обещаны
  и как аварийное средство.
- Откат деплоя на код **старше I0-минимума** стирает `history`, `career` и журнал учтённого; локальная работа недель
  такого кода возвращается только откатом этих недель и перезапуском
  ([правила](local-sources/05-operations.md#откат-деплоя-и-потеря-kv)).
- После потери KV поле `late` до запуска `records-rebuild` кладёт всё в ключ «старше истории»; сам `records-rebuild` после
  I1-T — аварийная мера ценой одного цикла без грейса. В `late` нет имён проектов: серии проектов и суммы «за 4 недели»
  на опоздавшую работу не поправляются.
- `max_concurrency: 1` не разводит ретроспективу и пятничный cron (cron идёт мимо очереди): `/retro` вручную около
  времени cron не запускать. Входит ли задержка сообщения в 24 часа его жизни в очереди — не проверено.
- В первые месяцы коридор «обычного» виден редко: ряд начинается заново после смены метода часов и после I1. До ответа
  на №6 в отчёте соседствуют блок без минусов и колонка с отрицательными числами.
